# 经验库盘点与 staging 过滤实施记录（2026-11-03）

对应 [plan-07](plan-07-经验知识生命周期.md)。本批只做**盘点 + staging 过滤回归**；不调用模型、不使用 GPU、不直接改经验库源文件。

## 1. 盘点结论

| 项 | 现状 |
| --- | --- |
| 文件 | `targets/apple-m4-max/experience.md`，8326 字节 |
| 条目 | 9 个小节，全部 `Confidence: verified`（`:12,23,33,43,53,63,73,83,93`） |
| 其它状态 | 没有 `reported` / `stale` / `retired` 实例；过滤缺口在实施前是**潜在的**，不是已泄漏 |
| 误入条目 | `:99` 的裸 `- [harness b4131be13c4750c8] Add a tcenv.cli ab subcommand …`，挂在第 9 节之后，无 `Confidence`，是开发者工具请求 |

9 条 verified 的标题：累加器片段到 32 会溢出；矩阵单元与 SIMT ALU 的 fp32 吞吐相近；启动契约能把同一颗核拉开 1.6 倍；逐元素与归约已经贴着带宽屋顶；库没调好的融合算子是真机会；有的库已经换了算法；threadgroup 内存上限是 32768 字节；静态 threadgroup 占用降低常驻线程组数；被长度截断后把重试的思考降下来。

## 2. device 与 experience 的去重结论（人工盘点，不改文件）

- `device.md:13` 的 32768 B / 1024 threads 是**设备属性**，`experience.md` 同主题条目还包含插桩读数约两倍、动态与静态共享上限等边界。两者不是同一层信息，**保留 device 那一行**，详细实测留在 experience。
- `device.md:14` 的常驻线程组摘要已经写明"详细证据在 `experience.md`"，符合"device 只留设备属性和一行指针"的去重方向，**不需要再合并或删除**。

因此本批的人工去重结论是**维持现状**，没有为了显得有产出而改写两份文件。

## 3. 过滤规则（已实现）

`taic/experience_prompt.py` 的 `filter_experience_for_prompt`：

- 保留前言（证据等级约定）；
- 只保留带 `Confidence: verified` 的小节；`reported` / `stale` / `retired` / 未标注的小节一律排除；
- 保留下来的小节里，裸 `- [harness …]` bullet 也删除——它是人工 promotion 的原始记录，不是一条 verified 经验，要进提示面必须先由人整理成带 `Confidence` 的小节；
- 没有 verified 小节时只剩前言，不编造经验。

两个提示面共用同一函数：

| 提示面 | 改动 |
| --- | --- |
| 会话工作目录 | `stage_guidance`（`taic/kernel_agent.py`）对 `experience.md` 改为过滤后写入；`device.md` 与 reference skill 仍原样拷贝 |
| 检索 outline / lookup | `SkillIndex`（`taic/tools.py`）对 `experience` 先过滤再切段，未验证条目既不进目录也查不到 |

运行级快照 `agent_guidance/experience.md` **仍保存原始文件**，用于溯源与重放；只有进入会话工作目录的文本被过滤。
