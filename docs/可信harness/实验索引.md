# 实验与尝试索引

这份索引回答“哪些实验已经做过、结果是什么、证据在哪里、下一步是什么”。它不是效果证据本身：每条结论都不能超过对应记录的范围。

**保存规则**：`runs/` 在 `.gitignore` 中，原始 run 可能只存在于本机。每次付费或 GPU 实验结束后，必须把任务、臂、起始候选、模型、seed、预算、实际成本、主要数字、结论和证据路径写进本索引或它链接的仓库内文档。不能只留 run 目录名，也不能只留在对话里。

## 仍开放、不能忘记的事项

- **同窗口 A/A 对照有系统性偏移**：三次约 1.0262/1.0262/1.0358，区间不含 1.0；`ab` 的独立 executor 对照约为 1。解释之前，`resolvable_relative` 不能当校准分辨率，相关晋级门不能视为可信。
- **G1-M 路线 M** 仍是 shadow-only；premise 路线 P 的激活不能用来标记它完成。
- **G1-D 真实决策实验** 需要先出现更多可判配对和可测误判，不能仅凭当前 1/27 的覆盖率改规则。
- **G3 盲重现、G7 两级账本** 仍等各自数据触发。
- **G12 正式跨 target 晋升** 等第二颗真实芯片或真实 NPU run；模拟 NPU 不算。
- **G6 动态预算效果** 已有自然 run 审计，但只定位了省略位置；是否伤害搜索仍未测量，不能把省略 0 的态势块当成全部信息送达。
- **正式效果实验** 若要回答“overlay 是否改善 speedup”，必须另行批准 AB/BA 多对实验、使用 fresh confirmed 指标并预先写停止条件；当前 P1 单对不支持继续付费。

## 新实验的最小记录格式

```text
日期 / 实验名 / 假设
任务、target、dtype、size、起始候选 SHA、模型、run_seed
control/treatment 的各自配置与注入内容
预算上限、实际成本、是否调用 GPU/付费模型
主要测量（fresh confirmation 与 search best 分开）
结论：supported / no_gain / inconclusive / refuted
适用范围、反例、是否允许发布、下一步
仓库内证据文档与原始 run 路径（两者都写）
```

新条目必须链接到**仓库内**的证据摘要；如果只有 `runs/` 原始文件，先复制关键结果再登记。这样即使 run 目录以后被清理，实验假设、数字、成本和“为什么停止”仍然可找回。
