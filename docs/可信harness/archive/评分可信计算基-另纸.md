## 1. 立项入口与结果归属

先做**只读可写性核实**：记录实际 hmz/pi 版本与有效 fence，确认写核会话和 code agent 在
`local=ALL` 下究竟能否改写 `tasks/`、`tcenv/evaluate.py`、选择/确认/发布代码、实验驱动和检查器。
只读源码与配置、fake worktree 可用于准备；不启动搜索、付费模型或 GPU。未完成这项核实前，
不得把下面的 `scoring_surface`、anchor、observer 或白名单写成待上线的第一阶段。

结果分两类，不能混用「发布」：

- **合法收窄**（以 plan-03 的状态转移表为准）停止后续 overlay 注入；内核确认与发布仍走现有确认门。
  证据不足导致的 `host_unverified` 只禁止该 run 作为 **harness 采纳或效果证据**，不单独否决内核发布。
- **非法扩权、审计历史被改、静态评分字节被改或检查器不可信**，才同时作废内核发布与 harness 采纳/效果证据。

`select_diverse_parent` 当前只被测试调用，`diversity_archive` 默认关闭。下面的排序策略白名单是
未来专用实验路径；启用配置、接通生产调用和效果实验都要另行授权，不属于本附件的开工承诺。

3. **确认与门控**：`confirmation_se`、`batches_agree`、`choose_confirmed` 及其调用路径。
4. **发布绑定**：`taic/orchestrator.py` 中 remeasured kernel → published 的绑定、确认记录和运行配置。
5. **实验统计与执行**：`taic/harness_experiment.py` 的计划、采集、`paired_effect`、`summarize_result`、

6. **检查器与有效配置**：完整性检查器、闭包清单、排除规则、anchor、自动加载入口、构建配置，以及

`trust.toml` 与 `trust_audit.jsonl` 属于**动态控制面**，不按静态字节冻结；其唯一状态转移正文在

## 3. 三类策略面与动态控制面

### 3.1 `scoring_surface`

上述静态评分字节必须两臂一致，且相对宿主 anchor 无未授权差异。普通 run 中发现改动即 `invalid`；
control 的冻结 patch 是空 patch，所以除合法动态控制事件外，全树总 diff 必须为空。

treatment 的总 diff 必须等于冻结 `treatment.patch`，且不得触及 `scoring_surface`。触及后按
`human_gated` 退出普通效果对照；只有第 3.3 节的闭集白名单函数可进入专门重冻结路径。
动态控制事件不是 treatment patch 的内容，按 plan-03 逐臂核对。

### 3.2 `harness_behavior_surface`

treatment 合法可变的是 overlay 内容与渲染、注入路径、TASK 组装与裁剪、反馈/提案生成与路由、
提示与上下文构造、经验选择和 `taic/flows/**` 的 session 编排。只改这些不应被评分完整性门误杀；
但 P2 人审、实验授权、预算和 GPU 边界不因「合法可变」而豁免。

### 3.3 `policy_hypothesis_surface`（闭集）

当前唯一候选是 `taic/policy.py::select_diverse_parent`，不是「TCB 里想改的任意一项」。
新增入口必须先在本文与验收中具名登记并人审；改名、包装、复制或搬模块不算白名单。

若将来启用，必须同时满足：

- 签名保持现状；只读候选和 `best` 的 `eligible`、`recheck_rejected`、`source`、`speedup`、`label`，
  以及既有纯函数 `feature_signature`/`_hamming` 或内联等价实现；不得读评分材料、容差、协议、预算、
  trust、确认池或进程环境。
- 返回入参 `candidates` 中同一个对象或 `None`；任何返回候选的路径都先保留 `eligible` 与
  `not recheck_rejected` 过滤。不得返回非 eligible、recheck_rejected 或新/拷贝对象。
- 函数与调用的纯函数均无副作用；宿主在调用前后对 `candidates` 与 `best` 做深快照比较。
- diff 仅限该函数体，不改签名、不新增辅助函数；冻结新 `protocol_version` 与 anchor，两臂由宿主
  用同一测量路径从原始 artifact 计算效果。变化的是排序策略，不是 correctness、统计、确认或发布尺子。

数值正确性、容差、安全/反作弊、`candidate_eligible`、确认与发布、证据/信任/权限、实验统计与 verdict、
协议/预算、执行控制、检查器与 anchor 永远不属于此类；不能借改名进入。

## 4. anchor、运行期与动态状态

- 宿主在 agent 启动前从 `base_commit` 的 Git 对象导出闭包与逐路径 SHA，记录 HEAD、`git_dirty` 和
  treatment patch SHA。普通 run 没有 `base_commit` 时须启动前冻结 HEAD，否则 `unresolved_base`，
  结果只能诊断。anchor、清单和检查器若在 agent 可写区，只能 `host_unverified`，不能自证。
- 静态 import 闭包从 `tcenv/evaluate.py`、`tcenv/bench.py`、`experiments/harness_cell.py` 与测试入口
  计算，并与上述命名面、数据根、自动加载入口取并集。动态导入、`site-packages`、运行时 monkeypatch
  仍是残余风险，不得写成完整安全证明。
- treatment 的 diff 规则不保护 control 或普通 run。每臂 trust 文件还要单独记录前缀 SHA，因为
  worktree 内的 `REPO_ROOT` 指向臂内副本；合法动态追加不计入额外 patch，但须按 plan-03 校验。
- 每个评测边界重算 TCB 与期望。静态评分改动、检查器/清单/配置不符、非法扩权或审计历史改写，
  停止 run 并 `invalid`；合法动态收窄只停止后续 active 注入，保留结果与审计。
- `host_unverified` 只禁止 harness 采纳/效果证据；不要把它扩张成「合法收窄也禁止内核发布」。
  非法扩权与评分篡改才同时禁止两类结果。

## 5. 以后实现时的离线验收清单

以下都是**规划 fixture，当前未实现、未运行**，不计入 plan-06 第一批完成定义：

1. 改 evaluator、`tasks/<task>/task.py`、未列出的 `tcenv` 模块、自动加载入口或生效配置 → `invalid`。
2. control 全树无非动态 diff → 通过；treatment 等于冻结 patch 且不触评分面 → 通过；额外 diff → 拒绝。
3. 改 `candidate_eligible`、确认/发布、`paired_effect`、`summarize_result`、实验 driver 或检查器自身，
   普通 run/control → `invalid`；treatment → `human_gated`，不得进入普通效果对照。
4. 缺 base/宿主 anchor、anchor 可写或检查器只能自证 → `unresolved_base`/`host_unverified`，不得采纳。
5. 合法 overlay/TASK/提示变化 → 评分门不误杀；改未生效 preset → 不触发本门，但必须记录生效配置。
6. 白名单正例只改 `select_diverse_parent` 函数体且满足全部契约 → 专用重冻结路径；改名/包装、
   返回非法候选、绕过过滤、改输入、改签名或新增辅助函数 → 拒绝。
7. 动态控制只引用 plan-03 的同一状态表做正反对照：合法自动 suspend/授权 append 不记 scoring attack；
   伪造 active/restore、未知扩权、自动 revoke、`revoked→suspended`、审计历史重写 → `invalid`。
   缺 observer/快照时按该表记 `host_unverified` 或 `invalid`，不得静默采纳 harness 证据。
8. 结果归属单独验收：合法收窄不阻断内核确认门，但阻断后续 overlay；`host_unverified` 只阻断
   harness 采纳/效果证据；非法扩权和评分篡改同时作废两类结果。

恢复只能从 commit 或「commit + 已批准 patch」重新冻结；真实 Metal/GPU 验证和真实校准另需具名授权。
