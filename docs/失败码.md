# 失败码

这页把仓库里带稳定 `code` 的 typed 失败翻成人话：**它是什么意思、常见原因、下一步做什么**。
日志里出现 `code=` 或异常类名时，先在这里查到对应行，再去权威源看实现。

`tests/shared/test_failure_codes.py` 锁住这张表与代码的双向一致：代码里新增一个 `code`
而没写进这里，或者这张表里留着一个已经不存在的 `code`，测试都会失败。所以这页不会自己长霉。

## 表怎么读

| 列 | 含义 |
| --- | --- |
| `code` | 异常对象上的稳定字符串，日志和测试引用它 |
| 含义 | 这一步在拒绝什么 |
| 常见原因 | 触发它最常见的三种改动 |
| 下一步 | 唯一一条先做的事；做完还不行再看权威源 |
| 权威源 | 抛这个错误的模块 |

## 任务合同与交付平面

| code | 含义 | 常见原因 | 下一步 | 权威源 |
| --- | --- | --- | --- | --- |
| `task_contract_invalid` | 任务合同本身不合法，是这一族错误的基类 | 直接抛基类、或子类漏了 `code` | 看具体子类的 `code`，它比基类更精确 | `tcenv/contract_errors.py` |
| `assembly_error` | 目录/文件/接口装配错，含 v1 与 v2 混放 | `tasks/<op>/` 里同时有 `task.py` 和 `opspec.json`；缺 `opspec.json`；`reference.py` 缺失 | `uv run python -m tcenv.cli tasks` 看发现阶段报的是哪个目录 | `tcenv/contract_errors.py` |
| `semantic_unresolved` | OpSpec、reference 与表示三者冲突，系统不替你选边 | `opspec.json` 的 dtype/shape 与 `reference.py` 不一致；`reference.py` 改了却没更新合同 | 人工定哪一侧是对的，改合同或改 reference，不要两边都动 | `tcenv/contract_errors.py` |
| `unsupported_contract_capability` | 要的能力超出当前合同版本，禁止回退到 v1 或伪造实现 | 用了未声明的属性/张量角色；想在 v2 里复刻 v1 的 lowering 注册表 | 在 `opspec.json` 里显式声明该能力；不能声明就先升级合同版本，别绕过 | `tcenv/contract_errors.py` |
| `reference_boundary_violation` | reference 越界：import 了候选、renderer 或 known-good，或改写了输入 | `reference.py` 里 `import` 了被测核；把输入张量就地改掉；返回了非法结果 | 让 reference 只读输入、只做数学；需要常量就写在文件里 | `tcenv/contract_errors.py` |
| `execution_geometry_invalid` | 执行几何、派生标量或参数绑定不合法 | launch 块里的 grid/threads 表达式含未定义符号；派生标量类型与内核签名不一致；多阶段参数绑定缺项 | 对照 `docs/架构/` 里该阶段的几何规则，先在 `naive` 路径跑通再改候选 | `tcenv/contract_errors.py` |
| `candidate_envelope_invalid` | 候选交付的 envelope（声明面）不合法 | 候选清单缺项、字段类型不对、声称的能力与文件不符 | 按 envelope schema 补齐声明；不要用"跑通再说"绕过 | `tcenv/track/envelope.py` |
| `portfolio_evidence_rejected` | 组合证据被拒：它不满足严格比较的相等/覆盖条件 | 分片证据缺失、身份不一致、用调优分片冒充未见分片 | 重跑产生该证据的那一步；证据不齐就把阶段留在 blocked | `tcenv/portfolio_evidence/projection.py` |

## 什么时候该新增一行

新增一个 `code = "..."` 的异常类时，同一个提交里：

1. 在这张表加一行，四列都写实（不要写「见代码」）；
2. 运行 `uv run pytest -q -n 0 tests/shared/test_failure_codes.py`；
3. 如果这个 `code` 会给 agent 看，`下一步` 一列必须是一条可执行命令或一个具体文件，不能是「检查配置」。
