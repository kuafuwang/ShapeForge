# 架构改进评估

这份文件回答：相对 2026 年公开的内核生成框架，这个仓库缺什么，以及 P0 到 P3 已经落成了哪些代码。数字来自 `runs/` 里已经写完的报告。搜索过程中的加速比不是对外结论。

状态只用这四个词。`已采用` 是代码在跑，默认值写在表里。`默认关` 是代码在，不开就不发生。`不采用` 是决定不做，或启动时直接拒绝。`空位` 是还没有工具，不能把空位读成已证明。

## 三个名字各管一个版本

`PROTOCOL_VERSION = "3"`、评测报告的 `schema_version = 4`、`loop_protocol = "flame_chase_1"` 是三件不同的事。数字碰巧接近，不表示可以互换。

| 名字 | 当前值 | 它管什么 | 和另外两个的差别 |
| --- | --- | --- | --- |
| `PROTOCOL_VERSION` | 字符串 `"3"`，定义在 `tcenv/schema.py` | 测量协议。计时窗口、确认批或目标上限变了就加。比较速度和花费时按 `protocol_epoch` 分成几桶。当前 `"3"` 放进第 3 桶 | 它不是成绩单的文件格式，也不是 `taic resume` 认的标签 |
| 评测请求 `schema_version` | 整数 `4`（`REQUEST_SCHEMA_VERSION`） | 父进程发给评测子进程的请求字段。版本 4 要求 `target_id`，并可带 `measure_serial` | 请求版本和报告版本现在都是 4，但是两套计数。缺 `target_id` 的旧请求会被拒绝 |
| 评测报告 `EvalReport.schema_version` | 整数 `4`（`REPORT_SCHEMA_VERSION`） | 成绩单 JSON 的字段集。读入只认 4，不把旧报告迁移成新报告 | `result.json`、`state.json`、`ledger.json` 自己的 `schema_version` 是 1，又是另一层 |
| `loop_protocol` | 字符串 `"flame_chase_1"`，写在 `run_config.json` | 这个搜索目录能不能被 `taic resume` 接上。当前代码只接这个字符串 | 它不启动 `hmz` 自带的 `flame_chase` 流程。历史运行若把测量协议记成同一个字符串，读侧把它放进 `protocol_epoch` 的第 2 桶，那是更早的一桶测量 |

## 这篇讲什么

- 文首 [决定一览](#决定一览) 用已采用、默认关、不采用、空位四词概括。三个版本号见 [三个名字各管一个版本](#三个名字各管一个版本)。
- 先说家底和「钱花在哪、为什么搜不到」，再看外部框架里哪些做法值得搬。
- 然后按 P0–P3 列出**已经落地**的代码：每项写清开关名、默认值和落在哪个文件。
- 最后列出**还没做**的事，避免把默认关闭的开关当成已生效的能力。

## 2. 钱花在哪，以及搜不到的原因

`runs/plan_type_analysis/REPORT.md`（2026-10-07）：159/1440 个回合被 48000 token 截断，147 次正文是空的，花掉 $9.33 / $28.73（32.5%）。14 个完成的 run 里 11 个第一颗合格核就已经到屋顶的 90% 以上，那之后还花了 $6.54 / $13.96（46.8%）。

`runs/apple-m4-max/truncation_replay/REPORT.md`：80 次请求，$4.098。丢掉回传的思考再问一次（`no_reasoning`，当时仍是 high）20 次里 14 次再次截断，只交出 4 颗核。`low_effort` 是 10 次再次截断、6 颗核，均价 $0.0474，低于 $0.0490。所以截断重试的默认强度现在是 `low`。

FlashAttention 的契约菜单 `runs/menu/fa-20261007-210204/summary.md`（该目录在当前检出里已不存在，下面是当时的快照）：三套契约各有发布数字，范围互相重叠（0.448–0.813、0.633–0.888、0.565–0.726），判定无结论。同一时期手写 GEMM 里，每组 SIMD 32 个及以上累加器片段的契约是 17880–35006 微秒，16 个及以下是 1361–1942 微秒（`runs/hw_features/REPORT.md`）。这档可以在进模型之前丢掉。

## 4. 已经落地的代码

### P0

- `LLMConfig.truncation_retry_effort` 默认 `"low"`。`"off"` 关掉思考，`"same"` 沿用原来的强度。命令行 `--truncation-retry-effort`。`experiments/truncation_replay.py` 增加 `off_effort` 臂。这一臂要花钱，本文件不跑它。
- `experiments/search_ab.py` 对已有文件的目录跳过，`--runs` 点名，`--which conv2d` 含 off 臂，`--max-total-usd` 用 `fits_cap`。
- `experiments.common.suite_metrics` 计算 `fast_p`。`summarize` 增加 `gain_over_naive` 和 `gain_per_usd`。`taic brief` 的 `counts.truncation_retries` 统计转录里被长度截断的回复。

### P1

- `search.plan_ledger`（默认开）。四类结果仍由 `taic/plan_ledger.py` 定义：`validated_win`、`validated_tie`、`falsified`（写对了但没变快）、`untested_impl_fail`（编译失败、接口错误、算错、不安全、运行出错、没写出核。这些还没被计时否定）。看板可按它重算。当前任务书不附这段。
- `search.diversity_archive`（默认关）。`taic.policy.select_diverse_parent` 还在：特征是源码级的七元组，不编译、不上 GPU，档案最多 4 个签名，慢于种子 85% 的不进。搜索循环没有调用它，`parent_label` 保持空。
- `experiments.contract_sensitivity.static_screen_contracts`：GEMM 用模板上的每组 SIMD 片段数，32 及以上丢掉；threadgroup 声明超过 32768 字节丢掉。`contract_menu --prescreen-top K` 先过这一关，并保留 `default`。`prescreen` 子命令只打印，不上 GPU。

### P2

- `search.fast_bench`（默认关）。只作用在搜索阶段的 `full` 计时：不测 `candidate_serial`；若 `~/.cache/ai_lowerling/fast_bench/`（或 `TCENV_FAST_BENCH_DIR`）里已经记下这个题的最快基线名，就只和那一条交错计时。确认测量不传这个开关。同一进程里，同一 `(题, dtype, 规模, 种子)` 的基线正确性输出会复用。
- `BenchStats.samples_s` 在有逐次样本时写入报告的计时块。`paired_bootstrap_speedup_ci` 用这些样本做配对重采样区间。没有样本的旧报告仍按原来的字段读。
- `search.experience_index` 指向一份 JSON 时，把最多 3 行写进这一场任务书。`exclude_task` 会丢掉同一道题的配对；索引没有 `pairs` 时不附提示。重复性实验把该路径置成空字符串。
- 评测请求的 `schema_version` 是 4，要求 `target_id`，并增加可选 `measure_serial`；报告版本是 4。版本 2 的请求有可选 `fast_bench`，版本 3 再加可选 `require_contract_launch`。报告版本 3 曾增加 `backend_version` 与 `timeline`。缺 `target_id` 的旧请求会被必填字段检查拒绝。只认识旧版本的子进程会拒绝新请求。父进程和子进程用同一套代码。
- `docs/诚实说明.md` 记下了截断重试默认降到 `low`；仓库里没有实现这次重试，字段只是记录。

### P3

- `plan_reasoning_effort` 和 `patch_reasoning_effort` 默认空，空就是沿用 `reasoning_effort`。命令行 `--plan-effort`、`--patch-effort`。截断重试仍优先用 `truncation_retry_effort`。
- 委员会成员可以在 toml 里写自己的 `reasoning_effort`。人数仍是每边恰好一名，名字仍是 first 和 second。
- `experiments/committee_ab.py` 默认只打印三臂和名义费用。`--execute` 拒绝启动，退出码 2。名义费用是臂数 × 次数 × 单次预算，不是账单上限。

## 5. 还没做、也不在这次代码里自动发生的事

- 不调用模型，不提交内核。`committee_ab --execute` 和截断回放的新臂都要另一次批准。
- `verify()` 仍是 `unsupported`。`differential_recheck` 仍默认关。
- 经验索引不会自己扫 `runs/`。要先调用 `build_experience_index` 再把路径交给搜索。
- 发布闸门不变：确认绑上源码，并且计时安静，才有对外加速比。
