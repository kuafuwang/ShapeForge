# 维护决策记录

记录会影响数据/协议、但不需要每次改代码的决定。新条目写在最上面。

## 2026-10-22 · `data/deleted` 保留 30 天，手动清理

- 默认 TTL：**30 天**（`taic gc --older-than-days 30`）。
- 默认只报告；只有显式 `--apply` 才删除，并在 `data/deleted/gc_log.jsonl` 追加审计行。
- 不做自动定时删除。运行 `taic gc` 的频率建议每月一次，或在大规模批跑前看一次 dry-run。
- 理由：删除不可逆；30 天覆盖一次“跑完—汇总—发现问题—回滚”的周期，又不会让 `data/deleted` 无限增长（当前约 266MB）。

## 2026-10-22 · `candidate_serial` 默认关闭，`eval_cache` 默认开启

- A/B 见 `docs/review/data_layer_20261022/SERIAL_AB.json`：串行对照占计时 GPU 的约三分之一；关闭后墙钟下降 4–8%，候选中位数差 −0.8% / +0.1% / +1.1%（在 2–4% 的 cv 内，无系统偏差）。
- `measure_serial = false`，`PROTOCOL_VERSION = "3"`；旧 run 保留 `flame_chase_1`/`2`，用 `protocol_epoch` 分桶。
- `eval_cache = true`：只复用 kernel/task/seed/mode/target/protocol/measure_serial 完全相同的报告；不同 seed 的确认批次照常测。A/B 见 `CACHE_AB.json`（同一次评测 4.41s → 0.68s，报告逐字段相同）。
- 需要再打开串行对照时：`--serial` 或 `measure_serial = true`。

- 现状：320 条 claim 中 `topic` 非空 **0** 条。写入端只有人工 review（`observe/feedback.py`），agent 输出没有 topic 字段。
