## 2026-10-22 · code agent 只做 P2 执行者，不做信任来源

- 已批准提案可以交给独立 code agent 在 worktree 里实现、补测试、生成 patch；人看 diff 后 apply/commit。
- code agent 不继承模型覆盖层的信任，不能自批、自 merge、改 `trust.toml`/预算/控制文件；改审查/P2 代码本身也走同一条人工闸门。
- `change_ref` 必须是 patch/commit 哈希；审计加 `implemented_by`/`approved_by`/`tests_run`。当前只实现 target experience 追加，代码补丁 worker 尚未实现。

## 2026-10-22 · `data/deleted` 保留 30 天，手动清理

- 默认 TTL：**30 天**（`taic gc --older-than-days 30`）。
- 默认只报告；只有显式 `--apply` 才删除，并在 `data/deleted/gc_log.jsonl` 追加审计行。
- 不做自动定时删除。运行 `taic gc` 的频率建议每月一次，或在大规模批跑前看一次 dry-run。
- 理由：删除不可逆；30 天覆盖一次“跑完—汇总—发现问题—回滚”的周期，又不会让 `data/deleted` 无限增长（当前约 266MB）。

## 2026-10-22 · `candidate_serial` 默认关闭，`eval_cache` 默认开启

- 2026-10-22 A/B（3 轮 × conv2d/flash_attention/relu）：串行对照占计时 GPU 的约三分之一；关闭后墙钟下降 4–8%，候选中位数差 −0.8% / +0.1% / +1.1%（在 2–4% 的 cv 内，无系统偏差）。完整说明见 `docs/架构/数据层.md` §3.3。
- `measure_serial = false`，`PROTOCOL_VERSION = "3"`；旧 run 保留 `flame_chase_1`/`2`，用 `protocol_epoch` 分桶。
- `eval_cache = true`：只复用 kernel/task/seed/mode/target/protocol/measure_serial 完全相同的报告；不同 seed 的确认批次照常测。A/B：同一次评测 4.41s → 0.68s，报告逐字段相同（见 `docs/架构/数据层.md` §3.5）。
- 需要再打开串行对照时：`--serial` 或 `measure_serial = true`。
