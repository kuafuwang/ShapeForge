# 当前工程做不到什么

本文只写边界。系统怎么分工见 [架构说明.md](架构说明.md)；这条路线替代了哪些人力、没替代哪些见 [算子工程师边界.md](算子工程师边界.md)。不需要先懂机器学习。

读完记住四句：

1. **算对是抽查，不是证明。** 没找到错例，不等于所有输入都对。
2. **留下的那一版可以比现成库更慢。** 另开一次搜索，默认不拿上次的好稿接着改。
3. **图形芯片同时画屏幕。** 超时会杀掉进程，死循环仍可能把电脑冻住几秒，甚至要按电源键重启。
4. **论文的方法在这台机器上只对上了一部分。** 搜索有时能接近现成库。「再多告诉模型硬件细节就会更快」没有测出来。论文用 GPT-6 Astra。我们默认是 DeepSeek 的 flash 和月之暗面的 kimi 轮流写，写内核只走 hmz，一轮一场。旧的直调运行不能用当前预设复现。FlashAttention 把预算加到 15 美元之后，搜索过程里最好到过 1.004 倍，确认复测是 0.987 倍；那份旧结果没有绑上源码，按今天的发布闸门不能当对外数字。他们在 NVIDIA 上的具体倍数，我们没有重跑，核验不了。详见第 6 节。此前 kimi 运行如果按 `models.json` 里偏高的单价入账，账会偏高；单价已改成 hmz 价目表上的美元价。

系统提示从 2026-10-21 起带上当前目标的 `device.md`。关工具时，`experience.md` 的来源路径也在提示里。这些路径改到 `runs/apple-m4-max/` 之后，`tests/golden/hw_off.json` 于 2026-10-21 22:41 又录了一次。此前请求的前缀缓存对不上，按 token 计的费用也会变。

## 1. 先别把它当成什么

| 容易当成 | 实际是 |
| --- | --- |
| 一个能编译任意计算的编译器 | 只做仓库里写好的那些题。要加新题，得自己交题目、标准答案、现成库和一份写得慢但算得对的小程序 |
| 大模型保证写出更快的程序 | 它只写文字。留下的稿子只是这次搜出来的里面，又安全、又在抽到的输入上合格、并且比**这次里的其他合格稿**更快。相对现成库的倍数可以小于 1，小于 1 就是更慢 |
| 和论文里「证明与 Triton 等价、并且超过 NVIDIA 上的 Triton」同一句话 | 这里没有面向 Metal 的形式证明。可选的 triton-msl 对照是估计，而且比「超过 NVIDIA 官方 Triton」弱 |
| 下次会自动接着上次的好结果磨 | 再执行一次 `taic run`，会新建目录，让模型重新写第一版。要接着改上一份合格稿，得显式写 `taic run --from <上次目录>` |

验收仍然只是：自检命令能打出成绩单；搜索结束后目录里有 `result.json`，有合格稿时还有 `best.metal`。验收里没有「一定比 MLX 快」。

### 契约菜单何时算有结论

这条只用于契约菜单（`experiments/contract_menu.py` 的 `judge()`）。别的实验脚本打出表，不按这条判谁胜出。

每个契约至少要有 2 个发布数字。发布数字来自发布闸门（`experiments/common.py` 的 `conclusion_of_run`）：确认绑上源码，并且计时安静，才算一个数。`best_speedup` 不参与排名。某个契约只有 1 个发布数字，是个例，不能产生胜者。只有某一个契约的最小发布数字严格高于其余每一个契约的最大发布数字，才有胜者。其余情形，判定是无结论。

整笔预算放不进 `--max-total-usd` 而跳过的那一次，没有发布数字。已经写有 `result.json` 的子搜索不再重跑；闸门若给出发布数字，这个数仍参加判定。

## 2. 算对盖不住的洞

资格在代码里是 `EvalReport.eligible`：成绩单状态为 `ok` 就合格。它只表示安全检查过了，并且抽到的那些输入落在允许误差里。和当前种子逐字相同的提交状态是 `unchanged`，不调用评测，不算合格，也不把上一份加速比再报一次。失败的新内核留在文件里，由评测写它自己的关卡；把旧文件贴回去凑过自查，搜索不收。细则在 [架构/搜索.md](架构/搜索.md)。

`tcenv/verify.py` 的 `verify()` 是形式证明的空位。现在固定回答 `unsupported`（没有面向 Metal 的证明工具）。这个结果写进成绩单，**不参与**过不过。不能把「没证明」读成「已证明」，也不能读成「已证伪」。

一元 fp16 逐元素题可以把 65536 个位型都跑过。记录在 `correctness.coverage`，不在 `verification`。能写的句子是：在设备 Y、这一套启动契约、这次编译选项下，对这一档形状做了取值域扫描。零的符号不检查。这次扫描的容差是逐元素相对误差加次正规下限，不含整段参考值的 RMS。`publication_role` 由发布结论和这份记录现算，不写入 `result.json`：已确认、加速比不低于 1.005、并且扫描通过且源码哈希与题目指纹都对上，才是 `primary`。比库慢、扫描没做、或旧运行没有这份记录，都是 `fallback`。这仍然不包括线程是否互相独立、下标和边界、并发，以及其他启动配置，所以不是整个内核的证明。范围写在 `scope` 里，并且不改 `EvalReport.eligible`。

抽查本身还有这些边界：

- 输入是按名字造的几组随机数（普通、很大、很小、正负抵消、NaN 和无穷大等），不是所有可能的输入。
- 图形芯片用的是较粗的小数（FP16 或 BF16）。允许和 CPU 上更精细的答案有一点差。现成库自己更差时，允许的误差会放到库的误差的 2 倍，并且不超过 8 倍。所以「通过」可以是「没比一个本身就算得不太准的库差太多」。
- 安检只拒绝写明的 `while (true)` 和没有条件的 `for (;;)`，以及不是苹果标准头的 `#include`。一个条件看起来会结束、实际上永远不结束的循环，安检抓不住。
- 杀掉工作进程是事后补救。正在图形芯片上跑的小程序无法被中途抢走。单核的一次 command buffer 超过 2 秒会发杀死信号，芯片自检是 4 秒。流水线仍是一条 command buffer，等待是每段 2 秒、封顶 8 秒，自检再乘 2。超过这个数仍记成挂死，一次就停整次搜索。电脑仍可能卡住。
- 真正往芯片上扔死循环的测试默认不跑。

## 3. 更快盖不住的洞

- **对照可以很弱。** 有的题（例如 Lion、把权重压成比特再做的矩阵乘）没有现成的、把步骤合在一起的库算法。手写的慢版本已经超过对照时，倍数里有一部分是对照弱。
- **计时锁只管本仓库。** 别的程序同时用图形芯片，测出来的时间仍会变慢。波动太大时会重测，最多 3 次；三次都吵，成绩单会标成不安静，搜索仍可能收下这份数。
- **复测减小碰巧。** 结束时把最好的和误差范围内的并列者再用新随机数测一遍。这去掉「在很多嘈杂测量里挑最大的那个」的偏差，没有变成精确到百分之一个位数的保证。
- **确认阶段取中位，不取某一批的最大。** 每颗进入确认的候选跑 3 批独立输入（`search.confirm_batches`，可改；1 = 旧的单批），公布的是这 3 批**中位数**，结果文件里同时留 `confirmed_values`、`confirmed_worst` 与 `confirmed_best`：**中位**是可对外说的那个数，**最好/最差/极差**说明同一颗核在不同输入上差多少。极差大（比如超过 2%）时，这个数只应读作「这个量级」，不要当成能精确复现的百分点；极差很小才说明它稳。原因是换一批输入本身会带来 1–2% 的数据相关差异：`runs/apple-m4-max/conv2d-feedback-20261021` 里同一颗核在确认那批输入上慢 1.8%，单批读数会把这件事整段落进公布值。
- **启动规模不能改。** 切成多少块、每块多少路，写在题目的契约里。模型不能靠改开多少路来提速。
- **成绩单会被截短。** 发回给模型的文字大约到 6000 字为止。STATUS 后面先是数字头（上界、离下界或基线时间、利用率、计时波动、线程组内存），截断砍的是后面的散文。基线已经快过下界时，数字头不写离界倍数，并写明基线更快不是改算法的理由，含 ieee 在内的用例仍要跟参考对上。排在数字头之后的问题，它仍可能看不见。数字头从写进反馈的那天起才有。这一天之前的运行，提示里没有这几行，不能拿来和之后的运行直接比「提示变了没有、所以结果变了」。
- **交卷前的自查不报时间。** 所以它不能靠某一次碰巧很快给自己加分；相对地，它在正式判卷之前也不知道这份改动快了还是慢了。
- **帮它看芯片细节的开关默认关着。** 用 Instruments 录「还比现成库慢」的稿子（`profile_poor`）、静态检查缺了哪些芯片特性（`hw_feedback`）、每轮留一种小改（`plan_mix`）、搜索结束后再录优胜稿（`profile_best`），都要另外打开。关着时，它主要靠成绩单里的时间和「离理论最快还差几倍」。苹果这块芯片能稳定读到的硬件计数器，本来就比 NVIDIA 那套剖析少；没有事先准备好的 Instruments 模板时，更细的计数器读不到。
- **钱可以略微超出预算。** 闸门拦的是下一次请求。已经发出去的那一次仍会计费。供应商已经计费、本地转录还没写下时进程死了，续跑账本会少算（`cost_may_be_incomplete`）。`budget_events.json` 有一行没写上就丢掉，不能当成完整账单。这不是硬的美元上限。和供应商账单逐笔对账要另外授权。

## 4. 一次运行盖不住下一次

好结果会写在 `runs/<这次>/`：每一稿、`best.metal`、`result.json`。这个目录不进 git，换一台机器就没有。

| 你想做的事 | 现在会怎样 |
| --- | --- |
| 同一道题再搜一次，希望从上次的好稿接着改 | 默认不会。新目录，重新写第一版。要接着改，用 `taic run --from <上次目录>`。默认只抽 1 份第一稿（`init_samples`） |
| 批量实验里已经做完的题再跑 | 只在**同一个输出目录**里已有 `result.json` 时跳过。`run_suite` 和 `repeatability` 不传目录时每次新建带时间戳的目录，会再开一套 |
| 钱用完了，或进程中途死了，但已经有一份合格稿 | 可以加预算后续跑，网页上的「加预算」就是这件事 |
| 因为收敛或轮数用完而停下，但已经有合格稿 | 命令行可以 `taic resume --lift-count-limits`。看板「重置预算」还会给每个还能继续的搜索加 15 美元，并把轮数和耐心抬到 10 万 |
| 因为图形芯片挂死或模型接口出错而停下 | 不能续。要再搜就新开一次 |
| 中途死掉时一份合格稿都还没有 | 不能续。没有可以接着改的底稿 |

跨次会复用的只有机器测量：这台机器的最快速度、可选的 triton-msl 对照、批量实验里那份手写慢版本的参照。这些不是模型写过的好稿。

## 5. 机器和题目的范围

本节给改代码的人。只想知道能不能拿去当通用工具的人，到这里可以停。

- 目标是这台 Mac 的苹果图形芯片。没有 NVIDIA 那条路，也不做 FP8。
- BF16 / FP32 特别小的「次正规数」会被这颗芯片变成 0。测试里的很小的数因此停在还能正常表示的范围上，没有覆盖「小到会被变成 0」的那一档。FP16 的次正规数在测试范围内。
- Triton 在主环境里只是题目文本。用社区程序 triton-msl 把它编译成 Metal 要另装环境和苹果的 Metal 工具链；装不上，主路径仍能跑。那个对照按相对 MLX 的比例估算，不是和候选在同一次计时里头对头量出来的。
- 题目清单以 `tasks/__init__.py` 为准：`TASK_NAMES` 12 道，`PHASE2_TASK_NAMES` 再加 4 道。另有 `SEMANTIC_NAMES` 里故意把名字和注释写错的题，用来看模型是不是在读计算步骤。那几道题能失败。失败说明这一次它看了名字；通过也不说明以后每次都看代码。
- 新搜索的预设名是 `taic.llm.DEFAULT_PRESET`。具体预算和轮数在 `taic.toml` 与对应的预设文件里，不在这里再抄一份数字。没有记下预设的旧运行，续跑用 `base`。
- 网页不是纯只读。写入口在 `observe/app.py`：加预算、重置预算、改下次搜索的默认模型、停止正在跑的进程。权限检查在 `observe/actions.py` 和 `observe/settings.py`（回环地址、页面令牌、同源）。它不编译、不提交内核。页面上的分组见 [架构/可观测.md](架构/可观测.md)。
- 花费总额只升不降。切换前账本里的钱结转进索引；结转规则和哪些行不进总额，见 [架构/可观测.md](架构/可观测.md)。

## 6. 论文里的话，我们核对到哪

论文是 arXiv 2609.36800（仓库里的 `docs/2609.36800v1.pdf`）。它在 NVIDIA 上让模型把 Triton 改成 PTX，并报告超过或打平厂商库和 Triton 编译器。我们做的是同一套循环，硬件换成这台 Mac 的苹果图形芯片，目标语言是 Metal。所以下面只回答「这套方法在这台机器上是否像论文说的那样」，不回答「他们表里的 NVIDIA 倍数是否测错」。

记录日期：2026-10-07 的表，在 2026-10-20 按磁盘上的 `result.json` 改过已经结束的那几行。数字仍是当时那次搜索写下的字段。另开一次搜索，这些倍数会变。旧的 `runs/apple-m4-max/p1/` 结果大多没有 `confirmation_source_sha256`，按今天的 `conclusion_of_run` 不能当发布加速比。下面写的「确认后」是文件里的 `confirmed_speedup`，不是闸门放行的发布数字。

**对得上的。** 循环本身能工作：模型写核，机器编译、对答案、计时，只留下明显更快的一版。有余地的题会涨，已经贴着实测最快的题涨不动。

| 题 | 我们测到的 | 和论文哪句话对得上 |
| --- | --- | --- |
| Mamba-2（`runs/apple-m4-max/p1/mamba2`） | 从 0.62 倍涨到确认后的 1.46 倍（相对编译过的 MLX）。$3 花完时还在涨。离按直接算法算出的最快还有大约 2.3 倍 | 现成库没把这道题调到顶时，搜索能超过它 |
| 矩阵乘（`runs/apple-m4-max/p1/gemm_paper`） | 确认字段约 1.003 倍。优胜候选 `039_r10.p0.fix1` 的成绩单约 14.8 万亿次/秒，相对当时实测峰值约 1.01。以前写的 14.5 万亿次/秒、峰值 98% 对不上这份优胜核 | 搜索能接近已经调好的矩阵乘。引用前打开该候选的 `report.json` |

**对不上，或不能照单全收的。**

同一道题波动很大。只报最好的那一次，数字可以是测出来的，但不是典型值。论文的重复试验表如果给的是多次的均值，这个偏差会小一些。我们自己的 5 次重复还没跑完。

我们的主实验叫 `deepseek-flash`。按 [DeepSeek API 更新日志](https://api-docs.deepseek.com/updates)（2026-09 起，2026-10-04 仍如此），这个名字现在就是 **DeepSeek-V4.1-Flash**。`deepseek-v4-pro` 仍是上一代 **V4 Pro**，不是 V4.1 里更贵的一档。官方还没有 V4.1 Pro。V4.1 Flash 在 DeepSeek 自己的代码和智能体评测上高于 V4 Pro（例如 DeepSWE v1.1：74.2% 对 62.7%），V4 Pro 只在部分推理题上略高（GPQA Diamond：92.4% 对 90.9%）。所以 flash 比 pro 好，是版本差，不是「便宜的意外赢了贵的」。

同预算下换过一次 `deepseek-v4-pro`。那是一次搜索。它说明：换到上一代，没有补上和 Astra 的差距。

一句话：这套循环在有的题上能接近或超过现成库（Mamba-2 的确认字段约 1.46，矩阵乘约 1.00）。FlashAttention 那次 15 美元搜索的确认字段是 0.987。优胜核会用上硬件指令。再多给模型一些硬件反馈，加速比就会上去——这句话在这台机器上没有证据。模型不同是论文量过的真差距，预算在我们这边同样决定能搜多久。
