# 工程改进实施计划：先保证结论可信，再改善搜索效率

> 交接给实施 agent 的设计文件；**不是授权立即运行 GPU/调用付费模型**。制定时以 `docs/代理理论.md`、`docs/架构说明.md` 和当前工作区为依据。基线提交为 `cf482cb`，但工作区已有未提交的代码及文档改动；实施前须重新核对 `git status`、配置和正在运行的搜索，不能覆盖他人的修改。

## 0. 目标、事实与约束

**目标**：在不削弱机器安全、判卷可信度和论文口径的前提下，减少无效美元/GPU 时间，提高有余地任务的**确认后**加速比，并使每一个结果能够追溯到确切的配置和验证证据。

理论上的落点：模型提出动作（Metal），代理在有限美元、GPU 时间与不完全观察下选动作，`tcenv` 给可复核的观察。理性代理在这里不是让模型自己给方案打标签，而是让外层用可测量的收益、成本和不确定性决定**继续、评测、停止**。POMDP/BDI/ReAct/Reflexion 是理解现有循环的视角，不是增加框架层、训练模型或拆成多个聊天代理的理由。`docs/代理理论.md` 已否定「固定 bottleneck 再承诺一次」「按模型自报的访存/计算标签删方案」「删罕用 fallback」；本计划不把这些列为任务。

**已经有，不得重造**：`quick_check`、GPU 机器锁/worker 心跳、分支并发而 GPU 评测串行、噪声门槛、独立确认、`--from`、预算续跑、`run_config.json`（新 run）、`experiments/search_ab.py`、开关 `truncation_retry`、`stop_at_roofline`、`abi_guard`、`target_note`、`rich_history`、`status_lines`。后三者已经回灌目标、失败原因和剩余预算；`profile_poor` / `hw_feedback` / `plan_mix` 仍为可选实验。先完成这些开关的因果评估，不再默认叠加新的提示词。

**现有证据（不是跨配置因果结论）**：`runs/p1/fa_paper/result.json` 的搜索最好约 1.004、确认约 0.987；确认池另一候选搜索时合格、换种子后 `incorrect`。`gemm_paper` 确认约 1.003，`mamba2` 确认约 1.459；`fa_flash_prof` 和 `fa_flash_hw` 的单次确认值没有高于不加硬件反馈的历史 run。历史 run 的预算、模型、轮数、契约、开关及是否中途续跑并不相同。`runs/plan_type_analysis/REPORT.md` 在其历史样本中将无代码截断和饱和任务上的花费列为主要浪费，但这些是观察分析，不是新开关的效果估计。

**不可破坏的不变量**：

1. `eligible == status == ok` 只表示本次安全检查及抽样差分通过；`tcenv/verify.py` 的 `unsupported` 不是形式证明。不能把有限测试、16 位单输入取值枚举或实数语义验证写成任意 MSL/AIR 内核的全域证明。
2. 计时只在机器 GPU 锁保护下；超时后不得再启动 GPU，杀 worker 不承诺 GPU dispatch 已停止；真实挂死测试始终需要人工显式授权。
3. 搜索用成绩不等于发布用成绩。未通过独立确认时不能宣称确认加速比；旧 `best.metal` 路径兼容，但结果必须明确标识是否经过确认。
4. 转录中的计费用量和已完成候选是恢复依据；续跑不能重复收费或静默更换实验协议。新 UI/日志故障不得改变判卷与搜索结果。
5. 不将费用、性能、正确性、模型能力混成单个成功率；每项改动必须有一个**明确的反例测试和退出条件**。

### P0-A：运行协议、种子、预算和断点恢复

**问题**：新运行会生成带 `llm`、`search` 和系统提示 hash 的 `run_config.json`，但历史运行（如 `fa_paper`）没有；`taic/resume.py:infer_settings()` 只能从旧提示和 `state.json` 推断部分字段。`Orchestrator.seed` 被记在配置里，但 `_eval()`、`_quick()`、`_confirm()` 仍向评测传 `seed=None`。当前还允许通过控制文件增加预算、`max_rounds`、`patience`；配置快照本身不等于运行期间所有生效设置。

- **A1：有效配置清单**。运行开始时原子写入版本化 manifest（保留 `run_config.json` 兼容）：task 名/dtype/size、契约与题面 hash、模型与价格来源、所有有效开关、系统提示 hash、repo commit + dirty 标志、Metal/OS/设备信息及校准文件指纹；不写 token/凭据、不可在无权限时把凭据旁路导入。运行中只准显式改变白名单项（预算、轮数、patience）；每次变更写追加事件，含旧值、新值、操作者、时间、轮次。**写入失败不许悄悄启动一个自称可复现的新运行**；看板的遥测写失败仍可忽略。历史运行标 `provenance: partial/unknown`，不回填猜测成精确事实。
- **A2：续跑协议**。`taic/resume.py` 从 manifest + 事件得到有效配置；已知字段变更但无事件要拒绝或要求显式 fork 新目录，不能在一个历史 run 中静默引入新默认。对缺 manifest 的历史 run 提供 `--dry-run` 列出已知/未知项，允许手动注明 `legacy_unverified` 后继续（不改写历史）。恢复后保持记录的系统提示、模型消息、已完成分支、搜索种子与计费；确认优胜者不同于搜索种子时不能把错误的对象拿来续写。
- **A3：随机数口径**。为新运行生成并记录 `run_seed`，用稳定的 `(run_seed, candidate_id, phase, check_index)` 派生搜索评测种子，避免分支并发完成顺序改变输入；确认/反例检查使用隔离的 holdout 种子，搜索提示不得泄露 holdout 输入。每个 report 已有 seed，逐项回验。不要把「同种子复跑 LLM」宣称完全可重现：服务端采样、模型版本和热状态仍可能变。
- **A4：预算语义**。保留现有「下一请求前检查、在飞请求可能超」的软预算，显示最大在飞数、实际超支和实验总 cap。若要硬上限，另做预留/结算模式并测试并发 3 分支、工具回合、超时与取消；不为看似绝对的预算保证偷偷改现有价格/搜索行为。`observe/actions.py` 的更改默认模型、加预算、停进程等写操作要分别做回环地址、Origin/令牌、路径规范化/符号链接和进程归属检查；在 `OBSERVE_CONTROL_DRYRUN=1` 下验证命令，不得启动 GPU。

**离线验收**：假客户端和假评测器分别模拟并发返回顺序互换、部分转录/断电、两次恢复、变更中途退出、配置缺失与不兼容、外部控制加预算；同一运行中候选的派生 seed 和账本一致。对旧 run 的 `--dry-run` 是只读的。任何 resume 不重做已经记账且评完的分支。

### P0-B：反例优先的正确性与结果发布

**问题**：`fa_paper` 的 `r8.p2` 搜索阶段合格，但独立确认阶段 `incorrect`。这是现有抽样测试的具体反例；不能据此估算总体错误率，也不能把 `quick` 当形式验证。先定义结果状态，再加检查。

- **B1：选择与发布分离**。保持 `Candidate.report`（搜索判定）和 `confirm_report`（独立检查）为两个证据对象；`result.json` 增 `published_status`（如 `confirmed_ok`、`confirmation_failed`、`unconfirmed`）、对应报告路径和候选源码 hash；保留老 `best.metal` 的兼容语义，但统计脚本只在 `confirmed_status == ok` 且确认报告属于当前源码时展示确认值；失败时不可退回 `best_speedup` 冒充确认值。恢复时可区分 search seed 和 confirm winner。
- **B2：候选升种子的第二种子闸门，先小范围试验**。仅对将要成为新最优/噪声内并列的候选，用独立种子做**正确性**复查（`quick` 不计时、不替代 full 的 shader validation）；若复查失败，保存两个 report/seed/失败 case，标 `counterexample`，不升种子；若超时，按现有熔断停搜，不能把异常当作「核错」缓存。若复查通过仍只表示更强抽查。此闸门会增加 GPU 占用和等待，应先离线单测，再以 opt-in 同预算 A/B 检查「错误候选减少/确认成功率」与 GPU 时间，证明净收益后才默认打开。
- **B3：反例复现**。为失败复测保存最小必要的 task/dtype/size、源码 hash、seed、case、容差与 report；提供离线元数据检查和**人工许可后**的单进程 GPU 复测命令，不自动运行危险候选。分类区分 `incorrect`、`unsafe`、`timeout` 和测量噪声；不要自动把不通过的参考库当真值。

**验收**：假评测器模拟「第一种子 ok、独立种子 incorrect」、两候选确认一个失败、确认全失败、熔断、缓存命中、确认途中断再恢复；`result.json`、`best.metal`、摘要表和看板不能声称错误候选已确认。新闸门关闭时既有搜索行为保持不变。

### P1-A：量化目标和证据质量，而不是增加反馈字数

- **计时报告**（`tcenv/bench.py`、`evaluate.py`、`report.py`）：给确认值附重复次数、candidate/baseline cv、噪声标志及比值的不确定度估计；若采用重采样区间，保存原始逐次时间、估计方法和样本量，并区分配对交错测量与独立测量。对波动很大的测量显示「不确定」而非百分位精确的 1.00x。汇总用 `confirmed_speedup`，另列相同规格/口径的 naive 参照、LLM÷naive、相对 triton-msl 的**估计**，严禁混合不同预算/模型/契约/设备配置。
- **屋顶反馈**（`tcenv/profile.py`、`taic/feedback_extra.py`）：所用峰值是实测参考，不是数学上的硬件极限；`task.flops` 是指定算法的运算量估计。基线比估算下界还快（如 conv2d）只证明**当前下界假设不适用**，原因可能是不同算法、运算量估计、峰值标定或计时口径，不能未经证据断言必然用了 Winograd。`target_note` 给出实际基线时间、假设与不确定性；`stop_at_roofline` 只在基线未显著越过下界、计时安静、校准有效时生效，必要时留人为 opt-out。将此作为启发式停手，不说「已达物理最优」。
- **证据密度**：`rich_history`、`status_lines` 已实现，先评估其效用。保留编译/ABI/错误 case/绝对时间/可解释瓶颈等高信号项；加入 profiler 或静态硬件清单前要证明它改变诊断且提高**最终确认值/每美元收益**，不能只比较模型的解释词汇。失败反馈过长时按段保留优先级，而非盲目扩大 token 上限。

**验收**：构造「基线低于算法下界」「所有时序 CV 很大」「naive 自身快过库」「搜索最好 >1、确认 <1」的离线报告，验证汇总不会夸大。实际 GPU 计时需单独窗口人工批准。

### P1-B：受控实验是改代理策略的前置条件

用现有 `experiments/search_ab.py` 而不是新造第十一套运行器。按任务分层：饱和对照（如逐元素）、结构难题（FA/conv2d）、有余地题（mamba2），并保留 `gemm` 作为强基线。每个比较锁定 task/dtype/size/launch contract、模型具体版本、系统提示、预算、eval_reps、机型/温度/计时协议；记录生效的 run manifest。相同条件下不同搜索独立运行；用同一批固定确认输入降低方差，但不能把 holdout 回喂搜索。不要把不同日期/预设的旧 run 当作严格对照。

**微观层面的小实验（先回放，再择优进 A/B）**：`runs/plan_type_analysis/REPORT.md` 把大量无源码回复归因于推理 token 耗尽。利用现有 `experiments/truncation_replay.py`，固定记录在磁盘的 seed kernel、计划、系统提示和输入消息，每次**只变一个**因素：`reasoning_effort`、回复 `max_tokens`、截断重试是否丢弃 echoed reasoning；记「交出合格代码的比例/请求数/美元/耗时」，不能以少思考推断核会更快。`plan_mix` 的小改法也只作为 opt-in 对照：比较正确率、编译/ABI 失败率和**确认收益**；计划短不代表有效。其它微优化先做日志与错误分类，不增加 `lookup_msl` / `quick_check` 的默认额度，因为已有工具调用且会占 GPU。报告必须按来源、样本量与时间区分离线重放和真实搜索。

**最先回答三个决策问题**：

1. 六开关整体 on/off 是否减少截断无代码美元、重复 ABI 失败、饱和后美元，而不损失确认成功率和确认加速比？`search_ab` 尚需补齐 off 臂；先 n=3/臂试水并如实报不确定度，不够时按预设停止/继续规则增加重复；比较墙钟、GPU 时间、LLM 美元、超时/错误、确认后加速比的分布。
2. 第二种子升种子闸门是否减少最终 `incorrect`，而没有明显增加 GPU 风险和无效测量？只在 B1/B2 的离线验收后进行。
3. `profile_poor` / `hw_feedback` / `plan_mix` 是不是各有独立净收益？历史单次 FA 更差不足以证明普遍无效；先单因素或正交试验，费用预先批准，结果阴性就维持 opt-in。不要一次把更多信息默认喂给模型。

预注册对照、预算 cap 和停止条件；已有 `runs/plan_type_analysis/REPORT.md` 是观察性证据，不能当 A/B。观察每一行动后的 **LLM 美元、GPU 占用、是否给出源码、错误关卡、相对种子的收益**，不让模型自报「这一步预计有多好」代替收益；需要估计的只有「再采一个样本值不值」，该估计也必须在跨运行 A/B 中检验。一个方案只有在**确认值或单位美元的改善**达到预设门槛，且安全/正确性不变差时，才改为默认。若不确定，保持旧配置而不是根据单次最高分决定。

### P2：有界重构，不重写整个代理

- **先抽纯策略**：从 `taic/orchestrator.py` 抽出候选资格、噪声比较、并列池、停手判断的纯函数；把评测/LLM/文件 IO 留在编排器。`taic/resume.py` 的回放调用同一策略，避免两份近似但不一致的选择规则。用相同假报告跑旧版与新版的选择轨迹做 golden 对照。不是把 POMDP、BDI 或 RL 框架接进项目。
- **再做版本化工件**：worker request/report 单独建可验证的 schema/version 边界（当前 `EvalReport.from_json` 依赖 `EvalReport(**d)`），新旧字段通过显式迁移，不准旧父进程静默错读；报告和关键 checkpoint 原子落盘，坏文件应报「待人工检查」而非被批量脚本当成未做的任务重跑。转录为已记账请求事实，checkpoint 只加速恢复，不能替代或篡改它。保持 fake-worker 超时/锁等待测试。
- **最后拆遥测依赖**：`tcenv`/`taic` 调 `observe.publish/progress` 属于核心 → 展示层的逆向依赖；先定义无依赖的事件接口及 no-op 实现，再让 `observe` 读取/订阅。网页已包含**付费写入口**、更改默认模型、预算与停进程动作，不能描述为纯只读；迁移必须保留权限检查和既有 UI 行为。`tcenv/evaluate.py` 中的 schema、评测、监督三职责可按稳定边界逐项拆分，不以文件行数本身为重构依据。同步更新 `docs/架构说明.md` 与 `docs/诚实说明.md` 的任务数（当前 `tasks/__init__.py` 为 12+4）、默认预设、网页写权限及 `verify` 的证据范围；不要靠手工复制代码中的默认值维护三份真源。

**验收**：旧 CLI/结果 JSON 消费方仍可工作或得到明确版本拒绝；无 `starlette/uvicorn` 的核心测试不触发 UI 导入；跑 fake worker、resume、control、budget、observe 单测；历史 run 只读打开，不向其中补写未经证实的配置。

### P3：条件研究，不纳入本轮必做项

- **验证器**：`tcenv/verify.py` 保持 `unsupported`，除非有可审计的 MSL/AIR 语义与证明范围。即使穷举 65536 个 FP16/BF16 值，也只能说「一元输入数值域覆盖」；没有证明线程独立性、索引与边界正确、并发和所有启动配置时，不能称为整个 kernel 的完备形式证明。可以另做单元素表达式/有界配置的 proof-of-concept，状态必须写明 `scope`，与正式 `eligible` 解耦；不先移植 NVIDIA/PTX 验证器后暗称 Metal 已证明。
- **契约调优与跨次知识**：`grid/threads` 目前由题目固定；已有 GEMM/FA 契约敏感性实验，先比较同预算和重复下的确认值，再决定是否让代理提出经过白名单验证的变体。跨 run 经验索引只有在重复成功的策略被识别出来、无语义泄漏到 holdout、可撤销且经 A/B 证明净收益后才考虑。不要让 LLM 自评标签成为硬过滤器，也不要把样例最佳核偷偷放进独立重复性实验的初稿。
- **代码级性能**：FA 要分开检查 tile/寄存器压力、threadgroup memory/barrier 和算法差别；conv2d 要先查 vendor 基线与直接卷积的工作量是否可比；mamba2 要始终对 `mlx_half_compile` 这类**最强**基线报告。任何所谓微优化均先跑完整正确性、独立确认及带噪声区间的性能比较，不能只看 kernel 源码或一次计时。

## 2. 实施 agent 的任务卡

按表中顺序逐包交接，后一包不得假定前一包已完成；先审查并测试前包提交。每张任务卡只指定**一个**写代码的 agent，可并行安排只读 reviewer；与工作区现有未提交修改冲突时停下请求决策，禁止覆盖。

| --- | --- | --- | --- |

## 3. 交付与停机规则（实施 agent 必填）

每个工作包交付：变更文件列表、受影响的旧 run/JSON 格式、设计不变量、离线测试命令与输出、是否动 GPU/花费美元、至少一个反例测试、A/B 所需预算与样本量、回滚方法、未解决风险。**写代码不等于批准实验**：默认仅运行不启动 GPU/LLM 的测试；涉及 `tcenv.cli naive/eval`、`experiments.*` 的实测或付费调用须先确认 GPU 空闲、机器锁与预算上限，并得到单独批准。不得运行 `TCENV_ALLOW_GPU_HANG_TESTS=1`。

验收的终点是：用一个新运行目录的 manifest 和报告，第三方能区分配置、搜索 seed、独立确认、验证范围和费用；旧目录不被篡改；确认失败不会成为合格胜者；A/B 可以据确认值和花费作出「保留/撤回/仍未知」的决定。若这些门槛未达，不进入「更多反馈」「训练代理」「形式证明任意 Metal」之类的研究扩展。
