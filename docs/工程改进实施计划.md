# 工程改进实施计划：先保证结论可信，再改善搜索效率

> 交接给实施 agent 的设计文件；**不是授权立即运行 GPU/调用付费模型**。制定时以 `docs/代理理论.md`、`docs/架构说明.md` 和当时的工作区为依据；写作期间 HEAD 及工作区仍在变化。实施前须重新核对 `git log -1`、`git status`、配置和正在运行的搜索，不能覆盖他人的修改，也不能把旧运行当作新协议的结果。
>
> **这些任务为什么值得做**（这条路替代了哪些人力、没替代哪些）：[算子工程师边界.md](算子工程师边界.md)。**每个数字能声称到什么程度**：[诚实说明.md](诚实说明.md)。三份文档冲突时，以 `runs/` 下的落盘证据为准，并回头改文档。

## 0. 目标、事实与约束

**目标**：在不削弱机器安全、判卷可信度和论文口径的前提下，减少无效美元/GPU 时间，提高有余地任务的**确认后**加速比，并使每一个结果能够追溯到确切的配置和验证证据。

理论上的落点：模型提出动作（Metal），代理在有限美元、GPU 时间与不完全观察下选动作，`tcenv` 给可复核的观察。理性代理在这里不是让模型自己给方案打标签，而是让外层用可测量的收益、成本和不确定性决定**继续、评测、停止**。POMDP/BDI/ReAct/Reflexion 是理解现有循环的视角，不是增加框架层、训练模型或拆成多个聊天代理的理由。`docs/代理理论.md` 已否定「固定 bottleneck 再承诺一次」「按模型自报的访存/计算标签删方案」「删罕用 fallback」；本计划不把这些列为任务。

**已经有，不得重造**：`quick_check`、GPU 机器锁/worker 心跳、分支并发而 GPU 评测串行、噪声门槛、独立确认及 `confirmed_status`、`--from`、`taic resume --dry-run`、预算/轮数/patience 的控制文件、`run_config.json`（新 run）、`search_seed_label` / `confirm_winner_label`、看板令牌/同源校验和 dry-run、`experiments/search_ab.py`。开关 `truncation_retry`、`stop_at_roofline`、`abi_guard`、`target_note`、`rich_history`、`status_lines` 已存在；后三者已经回灌目标、失败原因和剩余预算。`profile_poor` / `hw_feedback` / `plan_mix` 仍为可选实验。先完成这些开关的因果评估，不再默认叠加新的提示词。

**现有证据（不是跨配置因果结论）**：`runs/p1/fa_paper/result.json` 的搜索最好约 1.004、确认约 0.987；确认池另一候选搜索时合格、换种子后 `incorrect`。`gemm_paper` 确认约 1.003，`mamba2` 确认约 1.459；`fa_flash_prof` 和 `fa_flash_hw` 的单次确认值没有高于不加硬件反馈的历史 run。历史 run 的预算、模型、轮数、契约、开关及是否中途续跑并不相同。`runs/plan_type_analysis/REPORT.md` 在其历史样本中将无代码截断和饱和任务上的花费列为主要浪费，但这些是观察分析，不是新开关的效果估计。

**不可破坏的不变量**：

1. `eligible == status == ok` 只表示本次安全检查及抽样差分通过；`tcenv/verify.py` 的 `unsupported` 不是形式证明。不能把有限测试、16 位单输入取值枚举或实数语义验证写成任意 MSL/AIR 内核的全域证明。
2. 计时只在机器 GPU 锁保护下；超时后不得再启动 GPU，杀 worker 不承诺 GPU dispatch 已停止；真实挂死测试始终需要人工显式授权。
3. 搜索用成绩不等于发布用成绩。未通过独立确认时不能宣称确认加速比；旧 `best.metal` 路径兼容，但结果必须明确标识是否经过确认。
4. 转录中的计费用量和已完成候选是恢复依据；续跑不能重复收费或静默更换实验协议。新 UI/日志故障不得改变判卷与搜索结果。
5. 不将费用、性能、正确性、模型能力混成单个成功率；每项改动必须有一个**明确的反例测试和退出条件**。

### P0-A：在现有配置与恢复协议上补缺口，不另造一套

**现状**：`taic/control.py` 已定义 `CONFIG_FILE = "run_config.json"`、`budget_events.json` 和原子 JSON 写入；`taic/orchestrator.py:_write_run_config()` 已保存 llm/search 与提示 hash，但吞掉写入失败。`taic/cli.py:prepare_resume()` 和 `taic/resume.py:infer_settings()` 已提供 `taic resume <run_dir> --dry-run`、provenance 和既有退出码（不可续 3、锁冲突 4、配置/预算错误 5）。老 run 缺记录时目前用 `base` 默认值补未知项。这是需审计的**兼容行为**，不是尚未开发的能力。

- **A1：保留文件名，增加版本**。继续使用 `run_config.json`（`schema_version=1`），不新造 manifest 文件。保留现有字段；分别计算 `sha256(contract.describe().encode("utf-8")).hexdigest()` 和 `sha256(task.triton_source.encode("utf-8")).hexdigest()`，字段名 `contract_description_sha256`、`triton_source_sha256`，不做含糊的字符串拼接；写明范围不含 reference/baseline 实现。代码提交 hash + dirty 标记来自启动时 git 状态，采集失败记 `unknown`；设备与校准可在正常评测得到时写入 report，不为元数据提前触 GPU。不得写 API key/base_url/凭据文件内容。`run_config.json` 写入失败时，沿用现有 `Orchestrator.__init__` 的写入位置：让配置写入异常立即向上传递，`taic run` 捕获后以非零退出码 5 和明确错误退出；`experiments.run_one` 向调用者传递失败。**不进入 `run()`，不发付费请求，不写看似成功的 `state.json`/`result.json`**；可以留下该次创建的空目录，但不能删除或覆盖之前已有的运行目录。对 `--run-dir` 指向已有非空目录的**新运行**，在写配置前拒绝并提示用 `resume` 或新目录，防止重写既有 `run_config.json`/转录；只有明确 `resuming=True` 才允许使用既有目录。此项是由「吞错继续」到「拒绝启动」的明确兼容变更，必须单列假客户端测试。预算、`max_rounds`、`patience` 现有控制/事件机制不重写；只补明确的设置来源，若事件落盘失败不能声称「事件完整」。
- **A2：旧 run 先只做可见性审计**。保留老 run 现有 `taic resume ... --dry-run` 及原退出码；当关键开关来自 `preset/base/default (not recorded by this run)` 时，dry-run 和正式 resume 均显式列出**未知/默认补值**及来源。第一阶段**不拒绝**曾经可以续的旧目录，不新增 `legacy_unverified` 强制标志；如将来决定变更默认恢复策略，须另提 RFC，写明新 CLI 参数、老目录的迁移/拒绝范围及 3/4/5 退出码兼容。保持原系统提示、已经完成的分支、搜索 seed 与确认 winner 的区别。
- **A3：评测种子（独立小提交）**。现有 `Orchestrator.seed` 尚未用于 `_eval/_quick/_confirm`。仅新 run 在 `Orchestrator.__init__` 用 `secrets.randbits(64)` 生成并记录无符号 64 位 `run_seed`，同时给 `taic run` 增可选 `--seed`（十进制整数，校验 `0 <= seed < 2**64`；`resume` 不重新生成），正式候选/最终确认按以下**v1 字节配方**派生：`source_sha256 = hashlib.sha256(source.encode("utf-8")).hexdigest()`（源码是合约头拼接前的原文、小写十六进制）；`payload = json.dumps(["ai_lowerling/eval_seed/v1", run_seed, phase, label, source_sha256], ensure_ascii=False, separators=(",", ":")).encode("utf-8")`；`eval_seed = int.from_bytes(hashlib.sha256(payload).digest()[:6], "big")`。`phase` 只取 `search`、`confirm`、`recheck`；`label` 是评测前已有的稳定标签（如 `r2.p1.fix1`、`init.s2`、`prior`），确认沿用原候选 label，**不用评完后才分配的 `Candidate.idx`**。v1 golden vector：`run_seed=1`、`phase="search"`、`label="init"`、`source="kernel void k() {}\n"`，`source_sha256="ae97b4b6b017756328f7bbf1c39c8a871cf9f4857b583abcc236fce00e90d6e9"`，`eval_seed=96049487906312`；单测按此独立复算，避免实现或日后语言迁移时偏移。相同候选缓存复用时记录来源报告 seed，不声称在新种子测过；中断重试同标签同源码同阶段不得换种子。`quick_check` 工具调用缺稳定 call id，第一期维持随机种子并保留报告中的 seed，不宣称工具自查可按 run_seed 重放。旧 run 保持 `seed=None` 行为，不能伪造完全可重现性；相同 `run_seed` 也不能控制模型服务端采样、版本或 GPU 热状态。
- **A4：预算与看板是审计项，不是 A 卡的重写任务**。已有 `observe/actions.py` 的回环地址、Origin/令牌、dry-run 与进程控制测试；A 卡**不修改该文件**。进程若在 API 计费成功、transcript 写入之前死亡，恢复账本可能低估真实账单：在审计说明中写 `cost_may_be_incomplete`，与 provider 账单对账需另获授权；不得宣称硬美元上限。若审查发现现有权限漏洞，另开安全修复任务及 `tests/test_observe_control.py`，不把它混进配置卡。

**离线验收**：新运行产生且只产生一份无凭据的 v1 `run_config.json`；写入失败不发请求；resume 旧目录 dry-run 不写盘、兼容旧命令与退出码（不可续 3、锁冲突 4、配置/预算错误 5；新增警告不把原本成功的 dry-run 变成失败）；假评测器模拟两个分支评完次序交换仍得同一组 tag→seed、确认与搜索种子不同、缓存命中不伪称新种子；现有预算/轮数/patience 控制和账户历史测试继续通过。

### P0-B：反例优先的正确性与结果发布

**现状**：`fa_paper` 的 `r8.p2` 搜索阶段合格，独立确认阶段 `incorrect`。`RunResult.confirmed_status` 已有（取值 `ok`、`incorrect` 等），`search_seed_label` / `confirm_winner_label` 也已有；`tcenv/verify.py:VerifyResult.counterexample` 属于**形式证明接口**，不能装随机差分反例。先查消费方，再补遗漏，不造第二套状态词。

- **B1：沿用已有发布字段**。保留 `Candidate.report`、`confirmed_status`、`confirmed_speedup`、`confirm_report.json` 及 `best.metal` 的现有含义；**不新增 `published_status`，不改 `confirmed_status` 枚举**。为确认胜者在 `result.json` 补 `confirmation_source_sha256`（不改旧字段），以胜者候选目录的 `kernel.metal` 为来源；`experiments/common.py` 的读取/汇总与 `observe/scan.py` 的 `_speedup`、`run_detail` 是**本卡可写的消费端**，网页文字只有确有必要才改 `observe/static/index.html`。展示确认值时须同时满足 `confirmed_status == "ok"`、`confirm_report.json` 状态为 ok、`best.metal` 的 hash 与字段相同，且 `confirm_winner_label` 指向对应候选；汇总函数若目前拿不到 run 目录，可将目录作为明确参数传入，不能只看裸 `result.json` 猜测来源。缺失、`incorrect`、`crash`、`timeout` 时显示「未确认」，不得自动回退展示搜索时的 `best_speedup` 为对外结论。旧目录缺 hash 时显示「旧版未绑定源码」，不默认为已绑定；先加只读消费方离线测试。
- **B2：候选升种子的第二种子闸门，先小范围试验**。仅对将要成为新最优/噪声内并列的候选，用独立种子做**正确性**复查（`quick` 不计时、不替代 full 的 shader validation）；若复查失败，将两份 EvalReport、seed、失败 case 和源码 hash 记为候选的 `differential_recheck`（或独立的搜索复查文件），**不写 `VerifyResult.counterexample`**，也不升种子；若超时，按现有熔断停搜，不能把环境故障当作「核错」缓存。复查通过仍只是更强抽查。闸门先 opt-in + 假评测器测试；真实 A/B 的 GPU 与美元成本另申请。
- **B3：差分反例复现**。为失败复测保存最小必要的 task/dtype/size、源码 hash、seed、case、容差与报告；提供只读离线元数据校验和**人工许可后**的单进程 GPU 复测命令，不自动运行危险候选。分类区分 `incorrect`、`unsafe`、`timeout` 和测量噪声；形式证明接口仍 `unsupported`，不要改 eligibility。

**离线验收**：假评测器模拟「第一种子 ok、第二种子 incorrect」、两候选确认一个失败、确认全失败、熔断、缓存命中、确认途中断再恢复；`result.json`、摘要表及看板不能把未确认者称为确认成功。新闸门关闭时原有 `confirmed_status == "ok"` 的调用方/测试完全兼容。GPU 集成测试标记为可选、需另获授权，不能靠排除该标记的命令证明真实 GPU 行为。

### P1-A：量化目标和证据质量，而不是增加反馈字数

- **计时报告（第一期不改采样存储）**：`taic/orchestrator.py:speedup_se()` 已用 candidate/baseline 的 cv 与 reps 给比值算**近似相对标准误**。优先在纯统计函数中复用**同一公式**供确认报告和 `experiments/common.py` 使用；可以把公式移到 `tcenv/bench.py` 等中立依赖层，但不能反向让 `tcenv` 导入 `taic`。明确写明近似、n/cv、`benchmark.noisy`，**不把近似标准误称为有保证的 95% 置信区间**。对波动大的测量显示「不确定」。第一期不增加逐次样本字段，不改 `BenchStats`/report schema；若要 bootstrap/配对置信区间，须另立 P2 schema 升级，保存交错计时的逐次数据、方法及样本量。汇总只用 `confirmed_speedup`，另列相同规格/口径的 naive 参照、LLM÷naive、相对 triton-msl 的**估计**；严禁混合不同预算/模型/契约/设备配置。
- **屋顶反馈**（`tcenv/profile.py`、`taic/feedback_extra.py`）：所用峰值是实测参考，不是数学上的硬件极限；`task.flops` 是指定算法的运算量估计。基线比估算下界还快（如 conv2d）只证明**当前下界假设不适用**，原因可能是不同算法、运算量估计、峰值标定或计时口径，不能未经证据断言必然用了 Winograd。`target_note` 给出实际基线时间、假设与不确定性；`stop_at_roofline` 只在基线未显著越过下界、计时安静、校准有效时生效，必要时留人为 opt-out。将此作为启发式停手，不说「已达物理最优」。
- **证据密度**：`rich_history`、`status_lines` 已实现，先评估其效用。保留编译/ABI/错误 case/绝对时间/可解释瓶颈等高信号项；加入 profiler 或静态硬件清单前要证明它改变诊断且提高**最终确认值/每美元收益**，不能只比较模型的解释词汇。失败反馈过长时按段保留优先级，而非盲目扩大 token 上限。

**验收**：构造「基线低于算法下界」「所有时序 CV 很大」「naive 自身快过库」「搜索最好 >1、确认 <1」的离线报告，验证汇总不会夸大。实际 GPU 计时需单独窗口人工批准。

### P1-B：受控实验是改代理策略的前置条件

用现有 `experiments/search_ab.py` 而不是新造第十一套运行器。按任务分层：饱和对照（如逐元素）、结构难题（FA/conv2d）、有余地题（mamba2），并保留 `gemm` 作为强基线。每个比较锁定 task/dtype/size/launch contract、模型请求**别名**和接口参数、系统提示、预算、eval_reps、机型/温度/计时协议；记录生效 `run_config.json`。服务端若不报告底层权重版本，不能声称版本已被锁住：记录响应所示 model、provider、执行日期并在报告中声明版本不可验证。相同条件下不同搜索独立运行；用同一批固定确认输入降低方差，但不能把 holdout 回喂搜索。当前 `_eval()` 按并发分支**实际评完的顺序**更新 best，噪声范围内的候选与搜索轨迹可能随调度顺序改变；A/B 记录评测顺序，比较最终独立确认分布而非只对比某一条轨迹，禁止未经试验就强行按分支编号改选优次序。不要把不同日期/预设的旧 run 当作严格对照。

**微观层面的小实验（先回放，再择优进 A/B）**：`runs/plan_type_analysis/REPORT.md` 把大量无源码回复归因于推理 token 耗尽。利用现有 `experiments/truncation_replay.py`，固定记录在磁盘的 seed kernel、计划、系统提示和输入消息，每次**只变一个**因素：`reasoning_effort`、回复 `max_tokens`、截断重试是否丢弃 echoed reasoning；记「交出合格代码的比例/请求数/美元/耗时」，不能以少思考推断核会更快。`plan_mix` 的小改法也只作为 opt-in 对照：比较正确率、编译/ABI 失败率和**确认收益**；计划短不代表有效。其它微优化先做日志与错误分类，不增加 `lookup_msl` / `quick_check` 的默认额度，因为已有工具调用且会占 GPU。报告必须按来源、样本量与时间区分离线重放和真实搜索。

**批准单与费用**（实验任务卡 D 的交付物，不是 D 的执行授权）：D 卡把只读预检、缺失臂清单和下面的空白判定模板写到版本控制内的 `docs/实验批准单-搜索开关.md`，不写被 gitignore 的 `runs/`，也不在报告里代替 owner 签字。owner 填好之后还需在启动时另行明确授权；单有文件或预算数字不构成执行许可。现有 `experiments.search_ab --which fa --arm both --n 3 --budget 3` 会循环 FA 的 6 个固定目录，**没有跳过已完成 run 的机制**，不得直接拿它补跑缺失臂。若按 3+3 全部新开，名义承诺是 6 × $3 = **$18**；若经 `run_config.json` 验证 `fa_on_1`、`fa_on_2` 可沿用且 `fa_on_3` 与 3 个 off 仍未运行，仅缺 4 次，即 **$12** 的新名义承诺；`fa_on_2` 若还在跑先等待其结束再核算。先给脚本一个**拒绝覆盖既有目录、可点名缺失 run**的小改动/任务卡，离线测试完成且获批准后才能执行，不得复用同一目录去重启。当前脚本 `--which conv2d` 仅跑 on 臂；完整 on/off 要另列一次 off 运行（名义再 $3；若重做 on/off 则 $6）。这些加在 FA 后，名义新增预算分别可能是 $15 / $18 / $21 / $24，取决于重用与重跑的范围；逐项写入批准单，**都不是绝对账单上限**，LLM 在飞请求仍可能超支。`--max-total-usd` 是 `run_suite`/`repeatability` 的能力，当前 `search_ab.py` **没有**这个参数；不得假定用它就能给 A/B 硬限额。若将来加到 A/B，资金不足而跳过某次运行时须标记该臂不完整、停止作 3 对 3 的结论，另请追加预算。每次批准须写：任务/臂/次数、`--preset base`、模型版本、复用哪些旧 run、名义新增预算与可容忍超支、GPU 窗口、失败/挂死即停、执行人与报告人；未批准只允许生成清单与离线报告。

**最先回答三个决策问题**：

1. 六开关整体 on/off 是否减少截断无代码美元、重复 ABI 失败、饱和后美元，而不损失确认成功率和确认加速比？**先取得单独 GPU/美元批准，再**按批准单执行缺失的 off 臂；n=3/臂只是初筛，报告不确定度，不足时另请预算增加重复；比较墙钟、GPU 时间、LLM 美元、超时/错误、确认后加速比的分布。任一预定 run 被预算限制跳过或发生 GPU 熔断，标记该实验 `incomplete`，不再作为预注册的 3 对 3 判断；不足的样本须另请批准补齐。
2. 第二种子升种子闸门是否减少最终 `incorrect`，而没有明显增加 GPU 风险和无效测量？只在 B1/B2 的离线验收后进行。
3. `profile_poor` / `hw_feedback` / `plan_mix` 是不是各有独立净收益？历史单次 FA 更差不足以证明普遍无效；先单因素或正交试验，费用预先批准，结果阴性就维持 opt-in。不要一次把更多信息默认喂给模型。

预注册对照、预算 cap 和停止条件；已有 `runs/plan_type_analysis/REPORT.md` 是观察性证据，不能当 A/B。观察每一行动后的 **LLM 美元、GPU 占用、是否给出源码、错误关卡、相对种子的收益**，不让模型自报「这一步预计有多好」代替收益；需要估计的只有「再采一个样本值不值」，该估计也必须在跨运行 A/B 中检验。一个方案只有在**确认值或单位美元的改善**达到事前批准门槛，且安全/正确性不变差时，才改为默认。**实施 agent 不得自行填写改善百分比**：由 owner 在 `docs/实验批准单-搜索开关.md` **启动前**选择且锁定：(a) 主指标及计算式（例如两臂各次 `confirmed_speedup` 的中位数之差，或在确认性能不低于容许差的前提下比较美元）；(b) 最小有意义差异 δ 与允许退化幅度，均写数值及单位；(c) 正确性、安全、GPU 超时容忍度；(d) 样本量、缺样本处理、是否允许追加及最大追加数；(e) 各 run 软预算、实验总名义承诺、超支容忍额；(f) 决策规则 `保留/撤回/仍未知`。默认任一项未填、样本不足、两指标冲突或估计差异没过 δ，结果只记 `inconclusive/未获批准`，**维持当前默认**；不得事后换指标或挑最佳一次。n=3/臂只供初筛，不能只凭最高一次定胜负；改变 δ/样本量必须重新批准一个**新实验**。owner 填写文件后仍须另行明确批准付费/GPU 执行。D 卡的文档至少使用以下空白字段，执行者不能替 owner 填判定数值：

主指标和计算式：____  最小差异 δ（数值、单位）：____  允许退化：____
正确性/GPU 超时的失败判据：____  每臂样本数：____  缺样本及最大追加数：____

### P2：有界重构，不重写整个代理

- **先抽纯策略**：从 `taic/orchestrator.py` 抽出候选资格、噪声比较、并列池、停手判断的纯函数；把评测/LLM/文件 IO 留在编排器。`taic/resume.py` 的回放调用同一策略，避免两份近似但不一致的选择规则。用相同假报告跑旧版与新版的选择轨迹做 golden 对照。不是把 POMDP、BDI 或 RL 框架接进项目。
- **再做版本化工件**：worker request/report 单独建可验证的 schema/version 边界（当前 `EvalReport.from_json` 依赖 `EvalReport(**d)`），新旧字段通过显式迁移，不准旧父进程静默错读；报告和关键 checkpoint 原子落盘，坏文件应报「待人工检查」而非被批量脚本当成未做的任务重跑。转录为已记账请求事实，checkpoint 只加速恢复，不能替代或篡改它。保持 fake-worker 超时/锁等待测试。
- **最后拆遥测依赖**：`tcenv`/`taic` 调 `observe.publish/progress` 属于核心 → 展示层的逆向依赖；先定义无依赖的事件接口及 no-op 实现，再让 `observe` 读取/订阅。网页已包含**付费写入口**、更改默认模型、预算与停进程动作，不能描述为纯只读；迁移必须保留权限检查和既有 UI 行为。`tcenv/evaluate.py` 中的 schema、评测、监督三职责可按稳定边界逐项拆分，不以文件行数本身为重构依据。同步更新 `docs/架构说明.md` 与 `docs/诚实说明.md` 的任务数（当前 `tasks/__init__.py` 为 12+4）、默认预设、网页写权限及 `verify` 的证据范围；不要靠手工复制代码中的默认值维护三份真源。

**验收**：旧 CLI/结果 JSON 消费方仍可工作或得到明确版本拒绝；在新子进程使用 import hook 明确阻断 `starlette`、`uvicorn` 后仅导入 `tcenv` / `taic` 的核心判卷、策略和配置模块（避开明确属于 UI 的入口），不得因为 UI 包缺失而失败；也检查相关 UI 包未出现在 `sys.modules`。已装这些依赖的普通 pytest **不足以**证明解耦。跑 fake worker、resume、control、budget、observe 单测；历史 run 只读打开，不向其中补写未经证实的配置。

### P3：条件研究，不纳入本轮必做项

- **验证器**：`tcenv/verify.py` 保持 `unsupported`，除非有可审计的 MSL/AIR 语义与证明范围。即使穷举 65536 个 FP16/BF16 值，也只能说「一元输入数值域覆盖」；没有证明线程独立性、索引与边界正确、并发和所有启动配置时，不能称为整个 kernel 的完备形式证明。可以另做单元素表达式/有界配置的 proof-of-concept，状态必须写明 `scope`，与正式 `eligible` 解耦；不先移植 NVIDIA/PTX 验证器后暗称 Metal 已证明。
- **契约调优与跨次知识**：`grid/threads` 目前由题目固定；已有 GEMM/FA 契约敏感性实验，先比较同预算和重复下的确认值，再决定是否让代理提出经过白名单验证的变体。跨 run 经验索引只有在重复成功的策略被识别出来、无语义泄漏到 holdout、可撤销且经 A/B 证明净收益后才考虑。不要让 LLM 自评标签成为硬过滤器，也不要把样例最佳核偷偷放进独立重复性实验的初稿。
- **代码级性能**：FA 要分开检查 tile/寄存器压力、threadgroup memory/barrier 和算法差别；conv2d 要先查 vendor 基线与直接卷积的工作量是否可比；mamba2 要始终对 `mlx_half_compile` 这类**最强**基线报告。任何所谓微优化均先跑完整正确性、独立确认及带噪声区间的性能比较，不能只看 kernel 源码或一次计时。

## 3. 交付与停机规则（实施 agent 必填）

每个工作包交付：变更文件列表、受影响的旧 run/JSON 格式、设计不变量、离线测试命令与输出、是否动 GPU/花费美元、至少一个反例测试、A/B 所需预算与样本量、回滚方法、未解决风险。**写代码不等于批准实验**：默认仅运行不启动 GPU/LLM 的测试；涉及 `tcenv.cli naive/eval`、`experiments.*` 的实测或付费调用须先确认 GPU 空闲、机器锁与预算上限，并得到单独批准。不得运行 `TCENV_ALLOW_GPU_HANG_TESTS=1`。

验收的终点是：用一个新运行目录的 manifest 和报告，第三方能区分配置、搜索 seed、独立确认、验证范围和费用；旧目录不被篡改；确认失败不会成为合格胜者；A/B 可以据确认值和花费作出「保留/撤回/仍未知」的决定。若这些门槛未达，不进入「更多反馈」「训练代理」「形式证明任意 Metal」之类的研究扩展。
