### 7.1 `confirmation_publication` 要求批次数与 confirmed values 一一对应（R5 缺口）

`taic/policy.py`：在批次列表非空之后新增三条判定，任一不满足即 `{"allowed": false, "status": "未确认",
"reason": "not_confirmed"}`：

1. `len(batches) == len(values)` —— 每个 confirmed value 对应一批；两个测量值只有一条身份记录不再算「一致」。
2. 每一条批次的 `label` 必须**就是** winner —— 只检查「winner 出现在 labels 里」会让别的候选的记录顶替缺失的 winner 记录。
3. `result.confirmations` 里 winner 只允许出现一条 —— 重复的冻结记录会让 `by_label` 只保留最后一条、把前一条藏起来。

`experiments/common.py::synthetic_confirmation_documents` 随之改成**逐值一条**批次记录（`batches = [dict(batch) for
_value in batches_values]`）：夹具不得再依赖「一条记录为多个值背书」。受影响的既有夹具一并补齐记录数：
`tests/shared/test_r5_policy.py`（`_batches()` 两条、`confirmations` 仍是每候选一条）、
`tests/shared/test_publication.py`（三个值 → 三条记录）、
`tests/shared/test_observe_publications.py`（`batches_disagree` 与新增的 `incomplete` 都保留完整记录）。

负例（纯函数）：`test_two_confirmed_values_need_two_identity_records`、
`test_a_foreign_batch_cannot_stand_in_for_a_missing_winner_batch`、`test_a_duplicated_frozen_winner_record_is_refused`。
负例（读盘）：`test_r6_report_readers.py::test_two_values_with_one_batch_identity_are_not_published`。

## 12. 收窄复核：`hwfeedback` 缓存当前性（本轮，R6 仍是「待复核」）

### 12.1 当前代码的读取顺序（核对结果：正确）

`taic/hwfeedback.py::hw_feedback` 的顺序是

```
能力门（supports_hw_features）→ status != "ok" → document_state(rep) != "current" 直接 None
→ 才计算 key 并查 _CACHE → 计算 → 写 _CACHE
```

- 当前性判定在查缓存**之前**，且旧报告在这条路径上直接返回，不读也不写 `_CACHE`；缓存键仍是
  `(backend, task, sha1(source), speedup)`（未改语义），因为旧报告已不可能到达键与缓存。
- `_compute()` 自己的 `document_state` 门保留（防御性，也让直接调用者得到同样的拒绝）；`measured`、
  `roofline`、峰值与 `bound_beaten_line` 都在门之后读取，因此旧报告连一句性能文本都拿不到。
- `experiments/hw_feedback_ab.py` 与本文件的 CLI 入口都走同一条门（前者由 `EvalReport.from_json`
  拒绝非 4，后者走 `read_report_json` + `EvalReport.from_json`），本模块内没有第二条未加门的报告读路径。

### 12.2 修复前的失败形态（用 `git show HEAD:taic/hwfeedback.py` 原样加载旧模块复现）

- 暖缓存方向：schema-4 报告先出块（含 `Measured: 9.7 TFLOP/s = 66% …`）→ 同源码/速度的 schema-3 报告
  返回**同一份**块，`_CACHE` 里存的正是它。
- 最小旧字典（`schema_version: 3` + `roofline.achieved_gbps: 490`）在旧代码里同样出块，含
  `Measured: 490 GB/s = 98% of the bandwidth peak.` —— 与评审复现逐字一致。
- 因此两条回归在修复前都会失败：暖缓存后旧报告不等于 `None`；旧报告先来会把内容写进同一把键。
