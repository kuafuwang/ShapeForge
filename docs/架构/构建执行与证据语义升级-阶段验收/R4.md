## 2. `build` 闭集（§6.2）

新模块 `tcenv/build_projection.py` 是**唯一**投影与校验实现：

- `project_full(BuildOutcome, build_kind, identity)`：`full` 的两种来源之一（本进程成功构建）。
- `project_received(BuildEvidence, ...)`：`full` 的另一种来源（evaluator 已校验并加载的 prebuilt 集；
  无 `BuildOutcome`、不声称 NativeExecutable）。
- `project_partial(BuildError, ...)`：`partial` 的唯一来源（`error_class=compile`）；调用前用
  `require_build_error_projection` 复核附件，因此缺附件/artifact_set_digest 非空永远先变成基础设施失败。
- `validate_shape` / `validate_for_status`：字段闭集、`status↔shape` 表、provenance/artifacts/evidence/
  native 的交叉核对。读报告只校验，不补写。

| 要点 | 实现 |
| --- | --- |
| `build_kind` 来源 | `BuildProfile.build_kind`（builder 登记；`native`/`simulator`/`source_only`），**不是** wire 字段；Metal=`native`，FakeNpu/FakeTsm=`simulator`；host 无注册表时只查结构 |
| `assembled_sha256` | `BuildOutcome.assembled_sha256`（新增）：Metal 哈希装配后的文本；直通源 builder 哈希其编译单元；无独立表示时为 `null` |
| `native` / `native_digest` | 投影持有 live handle 的进程写 `NativeExecutable.document()` 并重算 digest；无 native 时 `native_digest=null` + `native_absent_reason`（native→`portable_artifact_set`，sim/source_only→`not_native_build`） |
| `artifacts` | `BuildEvidence.artifacts_document()` + 从 canonical manifest 重算 `artifact_set_digest`；有 `SOURCE` entry 时其 sha256 必须等于 `candidate_sha256` |
| `evidence` | 既有 `BuildEvidence.to_dict()`；status 只能 `ok/reused`；provenance/artifacts 与顶层逐字段相同；received 必须带 producer link |
| `opspec_digest`/`lowering_profile_digest` | 同一 `Specialization`（`MetalSourceBuilder.lowering_identity` / FakeNpu 同源）；无 Specialization 的诊断 builder 不能投影候选报告 |

`status↔shape`（`STATUS_SHAPES`）：`ok`→full；`compile_error`→partial；`abi_error/unsafe/incorrect/
runtime_error`→full；`rejected`→null 或 full；`timeout/crash/refused_hang/unchanged/duplicate/
external_duplicate`→null；`pending`/缺 status 不是持久状态，拒绝。

`EvalReport` 新增字段：`build`（必填键）、`evaluation_fingerprint`、`baseline_implementation_digest`、
`baseline_environment_digest`（后三者必填键，64 位小写 hex 或 `null`）。

## 3. 评测身份与 task-pack（§7.1/§7.2 中被 R4 硬验收的部分）

- `baseline_implementation_digest` / `baseline_environment_digest` / `_evaluation_fingerprint` 按 §7.2 的
  canonical 文档实现，用 `tcenv.identity.fingerprint`（§3.1 float 编码）；非整数数字先规范化。
- framework 登记表 `FRAMEWORK_LIBRARIES`（`mlx`/`torch`）；版本只用 `importlib.metadata.version`，可用性只用
  `importlib.util.find_spec`，**不 import 框架、不开设备**；版本不可识别时环境摘要与评测指纹都是 `null`。
- 本地 `task_pack_digest`：`tcenv/remote/task_pack.py::local_pack_digest` 对 track 登记的 pack 文件集算
  `{schema_version, files:[{path,size,sha256}]}` manifest 摘要；`tcenv/track/pack_digest` 委托同一实现，
  部署侧 `load_task_pack` 用同一形状。`local_provenance` 填入该摘要（不再留空）。
- 缓存（§7.1）：键文档由 `_eval_cache_identity` 组装；任一身份缺失 → 键为 `None`（**禁用缓存**，绝不把
  `null`/`"unknown"` 哈希成可复用键）。命中值必须 schema 4、`ok`、`full`，且
  `evaluation_fingerprint`/两条 baseline 摘要/候选 sha/opspec/lowering/sdk 与键相同；本地 Metal 还要求
  `build_kind=native` 且 `native_digest` 非空。Metal 且 `platform.mac_ver()` 不可读时不缓存。
  `sdk_version` 与 `BuildProfile` 同形（`macos-<release>`）。
