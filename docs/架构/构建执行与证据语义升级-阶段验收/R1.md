## 2. 本轮自行决定并登记的细节（规范要求“自行决定并记录”的项）

| 项 | 决定 |
| --- | --- |
| `flops`/`min_bytes` 的唯一来源 | **唯一显式结构化记账表达式**（`work_accounting.flops/min_bytes`，每项恰好一种量：`tensor` / `literal` / `symbols`，可带 `coefficient`）。不实现“语义推导器 + 手写值”双源；`task.py` 不再出现 `4.0 * M * H` 或 `(2*M*H+H)*2` 之类字面量（AST 用例覆盖）。规则版本 `WORK_ACCOUNTING_VERSION="opspec-work-accounting-expr-1"`，物化类型统一 **float** |
| `semantic_rules_version` | `"opspec-semantics-1"`（default 解析、dtype/shape 接受域、容差与实例物化规则） |
| RMSNorm `LoweringProfile` 字段闭集 | `{schema_version, name, backend_id, target_id, display_name, lowerer_id, kernel_name, grid, threads, constants, scalars, variant_params, variant_factory_id}`；`grid` 词是 int 或 `{symbol, factor}`，`constants`/`scalars` 的来源词是 `symbol:NAME`/`attr:NAME`/`literal:N`（完全解析后才进摘要，无 alias） |
| 注册位置 | profile 与 lowerer 登记在 `tcenv/backends/metal/lowering.py`，由 `tcenv.lowering.ensure_lowerings("metal")` 按需导入；R2 的 family/variant 登记沿用同一处约定 |
| lowerer / variant factory 身份 | `metal.rmsnorm` v`1`；非 variant 任务 `variant_factory = null` |
| `Spec_params` 与记账进入 OpSpec | OpSpec 增加 `spec_params`（有序符号表）与 `work_accounting` 两个键：§4.2 要求 RMSNorm 的替换 map 仍是 `{"M": str(M), "H": str(H)}`，附录 A 的示例又明确不预设记账写法，故由 R1 显式登记 |
| `description`、题面、known-good、dtype 拼写 | 全部归 `track.json`（不进 `opspec_digest`）；`triton_source`/`naive_msl` 由 track 渲染，`spec_params` 与旧 `load_text(extra=...)` 的替换 map 完全一致 |
| 模板里写死的启动/语义字面量 | `track.json::template_literals` 逐条登记（`num_warps = 8`↔`threads=256`、`i += 256`↔`threads=256`、`eps = 1e-6`↔`attrs.EPS`），并有 drift 用例：改 threads 前必须先把 `num_warps` 占位符化，改 EPS 前必须先把 `eps` 占位符化 |
| 非默认 target | `require_target_profile(backend, target_id)`：该 backend 一旦登记了 profile，未登记的 target 一律拒绝（不复用 default profile）；尚未登记任何 profile 的 backend 不受此限（fake/sim 后端保持原行为） |
| 旧指纹 | `task_fingerprint` v2 只对带 `semantic_instance`+`specialization` 的 task 生效；未迁移的 task 走**显式标注为 transitional** 的 pre-R2 哈希，R2 删除该分支（`tests/shared/test_task_assembly_structure.py` 与 `tests/shared/test_task_fingerprint.py` 固定了这两点） |

## 3. 硬验收逐条映射（§4.3 四条 + §9 R1 行）

### 3.1 §4.3-1：四个组合与 R0 冻结实现逐字节一致

对照物是 R0 基线包里冻结的旧实现：`docs/架构/构建执行与证据语义升级-R0/draft-files/tasks/rmsnorm/task.py`
与 `draft-files/tasks/_common.py`。用例按路径导入这两份冻结文件（并在测试期间把 `tasks._common`
替换成冻结副本），因此冻结的 `load_text` 读的是冻结模板，而不是本轮改写的 `tasks/**`。

覆盖：`Contract` 全字段（含 `gpu`）的 `dataclasses.asdict` 相等、`describe()`、`render_header()`、
`abi_stub()`、同一候选经 `assemble()` 的字节、渲染后的 `triton_source`、`naive_msl`、`description`、
`spec_params` 与旧替换 map。用例：
`tests/backends/metal/test_rmsnorm_lowering.py::test_the_derived_contract_matches_the_frozen_r0_task_byte_for_byte`
（4 个组合）、`::test_the_rendered_text_and_registered_identity_match_the_frozen_r0_task`、
`::test_spec_params_replace_the_old_text_map`。

### 3.2 §4.3-2：reference/cases/容差/exact/known-good/baseline 与记账数值不变

`::test_the_frozen_generator_and_reference_still_produce_identical_bytes`（4 个组合 × 5 个逻辑 case × 2 个 seed，
逐张量 `torch.equal` 比较输入与参考输出）、`::test_the_rendered_text_and_registered_identity_match_the_frozen_r0_task`
（cases/rtol/atol/exact/`flops`/`min_bytes` 数值**与类型**、baseline 名与 framework、`meta`）。
`flops`/`min_bytes` 统一物化为 float，数值与旧实现相同（paper: `67108864.0` / `67117056.0`）。
登记身份 `{implementation_id, implementation_version, params}` 在 `track.json`，参数由实现读取（不是第二份字面量）；
`pack_files` 覆盖 OpSpec、track、模板、lowering/opspec/track 模块、dtype 与 distribution 依赖，
`tests/shared/test_track_binding.py::test_the_pack_file_set_is_relative_existing_unique_and_symlink_free` 校验其存在性与形状。

### 3.3 §4.3-3：canonical/版本/派生字段的正负例

`tests/shared/test_identity.py`（9 个）：R0 的 7 个 canonical 向量用本仓 helper 重算一致；R0 数字编码样例逐条复算；
键序/空白不变；`1e-06`/`0.000001` 同一值；`0.0`/`-0.0`、`1`/`1.0`、`16777216`/`16777216.0` 三种不同；
NaN/±Inf/`2**53` 拒绝；NFC≠NFD；重复键与非 ASCII 键拒绝；**未规范化的裸 float 直接进既有 canonicaliser 必须失败**（N-12）。

`tests/shared/test_opspec.py`（20 个）：真实 OpSpec 通过校验且 `sizes` 只有 `paper`/`small`（F-5）；
必填字段/未知字段（顶层、张量、numerics、attrs、sizes、work_accounting）/越域 shape/`uses` 缺默认（F-4）/
domain 文法未知/EPS=0 拒绝；未声明 dtype/size 拒绝；重复键拒绝；**只改 shape 域而实例相同 → `opspec_digest` 变化**（F-1）；
**只改规则版本 → digest 变化**（F-24）；记账单一来源且 float；`SemanticInstance` 投影字段闭集；
cases 顺序与容差物化；`instantiate` 不修改已加载文档；`H=3` tail 可实例化但不进入发布域（F-6/F-5）。

`tests/backends/metal/test_rmsnorm_lowering.py`（23 个）：**只改 profile threads → `opspec_digest` 不变、
`lowering_profile_digest` 与 `task_fingerprint` 变化**（F-2/N-7）；**只改 lowerer 版本 → lowering 摘要变化**（F-25）；
`Specialization` 与实例不一致（digest 或 `spec_params`）时构造即拒绝；`Specialization` 投影闭集且 buffer `value=null`；
候选 `taic-launch` 改 threads 只改候选摘要（F-3）；profile 只登记一次、只覆盖 `apple-m4-max`（N-9）。

### 3.4 §4.3-4：结构检查证明 RMSNorm 不再手写 Contract
