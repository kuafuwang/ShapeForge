# A1 阶段验收：本地 OpSpec v2 主合同、任务合同/reference 入口与 Track 接口骨架

状态：**A1 已完成**。范围严格限定在 A1：v2 语义合同与 loader、标准任务目录、reference/表示/
baseline 边界、v1/v2 显式分派，以及 `TrackRegistry`/`TrackRenderer`/`TensorMemoryContract`/
`ExecutionGeometry`/`CandidateArtifact` 的冻结接口与 `tracks.json` v1 元数据骨架。
A2/A3 的 ABI 派生、几何解析/校验/构建和证据接入没有提前实现；A4/A5/A6 未开始。

## 1. 变更

生产代码（全部为新增，除 v1/v2 分派与导出所需的薄接点）：

- `tcenv/opspec/v2.py`、`tcenv/opspec/schema/opspec.v2.schema.json`
  - OpSpec v2 闭集 schema、语义校验、canonical `opspec_digest`（独立 envelope：
    `fingerprint_version=2`、`opspec-v2-semantics-1`）与 `SemanticInstanceV2`。
  - `load_opspec`/`validate_opspec`/`instantiate` 按 `spec_version` 显式分派；unknown version 拒绝。
  - v2 删除 `uses`；所有声明 attrs 必须带显式 default 并物化进 `resolved_attrs`。
  - attrs 只允许纯语义参数：标识符冻结为 `^[A-Z][A-Z0-9]*(_[A-Z0-9]+)*$`；
    `BLOCK_M`/`NUM_WARPS`/`THREADS`/`TILE_*` 以及大小写/连接变体（`Block_M`/`NumWarps`/
    `BLOCKM`/`NUMWARPS`/`BLOCK_SIZE`）和非法名（`EPS-value`/`EPS_`/`A__B`）一律拒绝。
  - 张量绑定 `role/shape/dtype/layout/stride/space/access`；`row_major`/`contiguous` 的 stride 与
    shape 在实例化时一致；符号维支持 `A*B` 形式的 stride。
  - `discovery` 是文档级发现元数据（`phase`/`default_instance`/`tags`/`summary`/保留的
    `variant_acceptance`），进入 `opspec_digest`，不进入 typed 语义、ABI 或 launch。
  - 没有全局 IR、pattern resolver、`StagePartitioner`、`LoweringRuleRegistry`；未知字段 fail closed。
- `tcenv/contract_errors.py`、`tcenv/task_presentation.py`
  - 稳定错误码：`semantic_unresolved`、`unsupported_contract_capability`（另有
    `assembly_error`、`reference_boundary_violation`）。
  - 唯一的确定性题面渲染器（事实模板，不读 track/tiling/作者）。
- `tcenv/taskcontract/`（新包）
  - `loader.py`：标准目录识别与显式分派、混合目录拒绝、v2 不回退 v1、`TaskContract`。
  - `reference.py`：`ReferenceRegistry` 与 `reference(inputs, attrs)` 固定接口；可选
    `gen_inputs(case, seed, instance)` / `error_scale(inputs, reference_outputs, instance, tolerances)`；
    `error_scale` 与 reference 一样接收工作副本，输入/输出原地改写会报 boundary 错误且调用方不变；
    AST 只读边界（禁止 import 仓库/候选/renderer/known-good，禁止文件/进程/eval 原语）；初值在进入
    reference 前先复制，调用方张量永不暴露给 oracle，`_version` 与调用前后内容 SHA-256 同时覆盖
    调用方与工作副本，捕获 `.data`/NumPy 视图原地写；结果
    键/形状闭合；`read_write` 初值必须在输入里、终值必须在结果里（含 role=output 的 read_write
    缓冲）；`reference_inputs`/`reference_outputs` 是这两个集合的唯一投影。`gen_inputs` 与 `reference.json.sampling` 是两个
    输入源，不能并存；只写 `opspec.json` + `reference.py` 的整数题可直接用自定义 `gen_inputs`，
    不经过默认采样器的整数拒绝。`ReferenceRegistry` 比较完整 reference 身份
    （source/version/sampling/error_scale/gen_inputs），不只是 `source_sha256`。
  - `display.py`：`display.json` 只允许 `description`/`spec_text`/`formula`；`spec_text` 仅
    G0 冻结的 `sem_*` 白名单（4 个固定题 + `sem_int_<1..18 位 ASCII 十进制种子>`；后缀按登记
    语法校验，不接受任意前缀、Unicode 数字、符号/指数/空白或 19 位拼写）；冗余 formula 与
    OpSpec 不一致判 `semantic_unresolved`；普通算子覆盖题面同样判 `semantic_unresolved`。

## 2. 合同行为

- **v1/v2 显式分派**：`load_standard_task` 先读 `opspec.json` 的 `spec_version`，v1 走旧
  `track.json` 读取，v2 走 `TaskContract`。v2 目录出现 `track.json`/`task.py`/`kernel_triton.py`/
  `naive.metal` 是混合装配错误；v1 目录出现 `reference.py`/`display.json` 等 v2 文件同样错误。
  新标准入口只覆盖目录型 task；生成族 `gen_*` 与动态 `sem_int_*` 继续走既有 `tasks.get_task`
  路径（身份不变），A5 逐题迁移时再决定其目录形态。
- **v2 无 fallback**：缺 `reference.py` 的 v2 目录直接 `assembly_error`，不会退回 v1。
- **v2 `@variant` 装配期拒绝**：调用方传 `variant` 非 `None`（包括空字符串）或
  `discovery.variant_acceptance` 非空都判 `unsupported_contract_capability`；variant 是候选自己的
  launch 选择，不是第二份题面。
- **语义冲突**：OpSpec/reference/表示冲突（题面覆盖越权、冗余公式不一致、reference 结果键/形状
  不闭合、`read_write` 初值缺失或终值缺失、reference 改写输入、`gen_inputs` 与 sampling 并存）判
  `semantic_unresolved` 或 reference 边界错误，不自动选边；改写输入只发生在工作副本上，调用方
  数据保持不变。
- **能力不足**：workspace 张量（等 A2 ABI）、未验证 track、无 ABI 的 render 都判
  `unsupported_contract_capability`。
- **reads/writes**：`reference_inputs = role=input ∪ 所有 access=read_write 张量`（包括
  `role=output` 的 read_write 初值）；`reference_outputs = 纯 write 输出 ∪ 所有 access=read_write
  张量`（终值）。生成、输入校验、reference 执行和采样计划都使用同一组初值；终值必须返回并纳入
  差分合同。A1 只冻结语义与 reference 合同，Metal `read_write` 的执行协议属于 A2/A4。
- **correctness_only**：没有 baseline 时 `TaskContract.baselines` 为空、`task_baselines()` 为空、
  `correctness_only=True`；A2/A3 接线 `Task.baselines` 时直接使用这个投影。
- **pass/fail 唯一公式不变**：A1 没有引入第二套判决；CAKE2 `precision.py/ulp.py` 没有被 import，
  也没有进入 `tcenv/taskcontract`。G0 的 82 个 v1 组合的 cases/tolerances/error-scale 实现身份保持
  不变（见 §4）。

本轮复审补齐的验收点（均有稳定测试/自检）：

1. v2 `OpSpec.digest_document()` 按 `spec_version` 返回 v2 envelope，`fingerprint(digest_document()) == digest`；
   v1 仍返回 v1 envelope。
2. 标准入口只有 `opspec.json` + `reference.py` 的整数题可用自定义 `gen_inputs`，不再先落入默认
   正态采样；`gen_inputs` 与 `reference.json.sampling` 并存判 `semantic_unresolved`。
3. `ReferenceRegistry` 比较完整 reference 身份（source/version/sampling/error_scale/gen_inputs），
   同源码但不同版本的包不能静默覆盖。
4. reference 在输入的工作副本上执行；越界改写会报错，但调用方张量值与 `_version` 不变。
5. `CandidateArtifact` entry role 必须是目标 track `candidate_roles` 的子集；全局合法但未登记的
   `launch` 等 role 也拒绝。
6. A1 只保留 `ExecutionGeometry`/`GeometryStage` 字段与字段投影；删除 `geometry_identity` 和具体
   几何校验，执行身份/解析/求值归 A2/A3。
7. 24 个 shipped v1 OpSpec/98 个组合的 v2 映射逐字段一致；RMSNorm/sigmoid 的 v2 reference 与 G0
   逐字节一致，RMSNorm 的移植采样器复现 G0 输入；op_desc 只读摘要按 CAKE2 模板闭集比较。
8. `display.spec_text` 的 `sem_int_` 后缀按登记语法校验（1..18 位 ASCII 十进制），
   `sem_int_not_a_seed`、非 ASCII 数字、19 位拼写均拒绝；新增稳定负例并覆盖完整
   `load_task_contract` 路径。
9. `tests/shared/test_op_desc_summary.py` 已加入 `FIXED_NODE_IDS`，固定入口实际包含它的 3 个测试。
10. 冻结面加入 `tcenv/task.py` 与 `tcenv/contract.py`；重放脚本直接防止任务身份/Contract 投影
    被后续改动绕过。
11. `read_write` 初值合同覆盖 `role=output` 的 read_write：`reference_inputs` 为 input ∪
    read_write，默认采样、`gen_inputs` 校验、reference 执行和结果检查共享该定义；RMSNorm y/acc
    参考实现实际读取 y 初值，并验证 y/acc 终值与缺失 y 初值的负例。
12. `load_task_contract(..., variant="")` 按非 `None` 拒绝，不再把空串当作“未传 variant”；既有
    稳定负例已覆盖空字符串。
13. 候选 entry path 逐段拒绝 `.`/`..`；`a/../b.metal`、`a/../../b.metal`、嵌套穿越以及 `.`/`..`
    本身都拒绝，并加入固定负例与 self-test。
14. v2 attr 标识符语法冻结为 `^[A-Z][A-Z0-9]*(_[A-Z0-9]+)*$`；几何 token 用去下划线/小写后的
    子串检查，覆盖 `Block_M`、`NumWarps`、`BLOCKM`、`NUMWARPS`、`BLOCK_SIZE` 等变体，非法名
    `EPS-value`/`EPS_`/`A__B` 同样拒绝。
15. 默认 dtype/size 只在 `is None` 时应用；`dtype=""`、`size=""` 和两者同时为空都进入既有域校验
