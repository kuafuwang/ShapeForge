## 1. 范围与不变量

P1 只做一件事：把 P0 的离线 exact dispatch 接到**真实执行**上，并且只在最后一步构建一个普通候选。

- 流程固定为：解析请求 → **exactly-one** dispatch → 对唯一 variant 用
  `resolve_geometry(..., instance=..., contract=abi, limits=limits)` 做**纯 CPU** 预检 → 需要时按已声明的
  `resource_unavailable` 切换到已声明的投影 `DomainFallback` → 只构建/执行最终选中的普通
  `CandidateArtifact`（`evaluate_task(..., fallback_geometry=None)`）→ 返回
  `PortfolioDispatchRecord + TaskEvaluationResult`。
- **不**创建 active `DispatchManifest`、不写激活指针或 `portfolio_run.json`（那是 P2）；
  **不**用 A2 的 `GeometryPair` fallback 冒充 domain fallback（`fallback_geometry` 恒为 `None`）；
  **不**让 `evaluate_task` 先抛资源错误再分流（资源分流发生在任何构建之前）。
- 缺候选 Host Tiling 的 variant/fallback 投影为 `msl-single`；带合法Host Tiling + 声明 workspace 的
  variant 投影为 `msl-bundle`；两者都保留各自源里的 `taic-launch`。
- 生命周期绑定**子候选** SHA 与实例几何，不绑定 parent portfolio SHA。
- `PortfolioDispatchRecord` 是 P0 的组合决策记录，刻意区别于 `v2_runtime.DispatchRecord`
  （同名类、同 schema id、同字段集都被 `tests/shared/test_shape_portfolio_runner.py` 和
  `P1/verify.py` 的静态自检拒绝）。

## 3. 垂直切片

### 3.1 有限题与命名实例

一个有限 elementwise 题 `y = -x`（`P1_OP = shape_portfolio_pointwise`），OpSpec 显式声明
`workspace scratch`。有限命名实例池（`P1_SIZES`）覆盖两个 dispatch 边界、奇数 tail 与覆盖空洞：

| size | N | 覆盖点 | 期望 provider | Track |
| --- | --- | --- | --- | --- |
| `tail` | 7 | 奇数 tail，第一边界之下 | `variant-b-single` | `msl-single` |
| `below` | 63 | threshold − 1 | `variant-b-single` | `msl-single` |
| `threshold` | 64 | 第一 dispatch 边界 | `variant-a-bundle` | `msl-bundle` |
| `above` | 65 | threshold + 1 | `variant-a-bundle` | `msl-bundle` |
| `hole` | 100 | 候选覆盖空洞 | `fallback` | `msl-single` |
| `boundary` | 128 | 第二 dispatch 边界 | `variant-b-single` | `msl-single` |
| `large` | 1024 | 同一边界远侧 | `variant-b-single` | `msl-single` |

### 3.2 两个 variant + 一个独立 fallback

- `variant-a-bundle`：guard `ge N 64 and lt N 96`；源 `device/variant_a.metal`，grid `N,1,1`，
  threads `1,1,1`，读 Host Tiling 写入的 `scratch`（每个 index 写 −1）再乘 `x`。Host Tiling 是
  **承重**的：计划不执行则 kernel 读到毒值，correctness 直接失败。它同时声明
  `host/geometry_a.json`，因此投影为 `msl-bundle`。
- `variant-b-single`：guard `lt N 64 or ge N 128`；自包含源 `device/variant_b.metal`，
  grid `N,1,1`，threads `32,1,1`，带边界检查；投影为 `msl-single`。
- `fallback`：独立 generic 实现 `device/generic.metal`，一个 threadgroup × 1024 线程的 grid-stride
  循环；不依赖候选 Host Tiling，投影为 `msl-single`；声明可用原因 `outside_candidate_coverage`。

三份 MSL 源都保留自己的 `taic-launch` 块（缺块被固定负例拒绝）。

### 3.3 组合器行为

`run_portfolio_task` 的顺序与拒绝条件（全部由固定 CPU 节点覆盖）：

1. `locator_for_instance(request)` 按请求的 `(dtype, size, usage)` 重新定位题与合同——几何只能为
   **该实例**解析，不能借用别的 size；
2. `ExactDispatchResolver.resolve(request, preflight=hook)`，hook 是纯 CPU 的
   `resolve_geometry(instance=..., contract=abi, limits=...)`；
3. 非 `resolved`/`fallback` 的结果（`dispatch_overlap`、`dispatch_unknown`、`dispatch_unmatched`、
   `semantic_unresolved`、`unsupported_contract_capability`、`variant_unavailable`）直接返回：
   **不返回最终 projection、不构建、不调用 `evaluate_task`**。源内 launch 的预检可能为被检查的
   provider 做一次**纯 CPU 临时投影**（`_preflight_hook` 的 `chosen is None` 分支）以导出其几何——
   这个临时对象随后被丢弃，因此这里不声称"零投影"；
4. 语义域外请求永不 fallback（fallback 是域内正确性 provider，不是语义逃生门）；
5. 只为最终选中者**返回** projection，并校验投影出的几何字节 == 父声明几何（`geometry_origin_sha256`）；
6. **两条 Track 都在构建前完成几何预检**：bundle 用冻结的 geometry entry；`msl-single` 没有冻结
   几何，则由 runner 用**请求实例**的合同调用注入的 launch 解析器导出源内几何，再走同一个
   `resolve_geometry(instance=..., contract=abi, limits=limits)`。因此"唯一 variant 的源内 launch
   超限"也由 dispatch 按已声明的原因分流（未声明则 `variant_unavailable`），而不是等到
   `evaluate_task` 里才炸；`record.preflight.status` 对两条 Track 都是 `ok`，并携带已求值几何；
7. 单源 fallback 自身超限 → `variant_unavailable`（"no chained fallback"），不构建、不评估；
8. 缺 Host Tiling、非法 Host Tiling、缺 launch 都在构建前拒绝；
9. 调用 `evaluate_task(..., fallback_geometry=None, lifecycle_factory=...)`，并校验返回的
   `TaskEvaluationResult`：provider 不得换标、child SHA ≠ parent portfolio SHA、artifact 不能失效、
   geometry/artifact/bundle/evaluation 身份一致、`runtime_provider == "candidate"`、
   `fallback_geometry is None`。

## 5. 验收方法

```bash
# 1) 录制真实设备证据（只跑 6 个固定 GPU 节点）
uv run python docs/架构/shape-portfolio-阶段验收/P1/verify.py --record-evidence
# 2) 重写交付 manifest
uv run python docs/架构/shape-portfolio-阶段验收/P1/verify.py --write-manifest
# 3) 完整验收（CPU 阶段 + GPU 阶段 + live==archived）
uv run python docs/架构/shape-portfolio-阶段验收/P1/verify.py
```

`verify.py` 的 CPU 阶段：manifest → P1 起点基线（钉住的字节、epoch 名、HEAD、79 文件合同面、路径指纹、
`tracks.json` 与 registry/Track digest、与 P0 记录逐字节交叉验证）→ A4–A6/P0 记录与 32 份冻结 evidence →
静态边界（注入适配器、无 backend import、无 active 清单概念、记录类型不同）→ fixture 路由重放（不编译）→
P0 复验（P0 manifest 与声明漂移、P0 历史记录、36 个固定节点、10 个回归文件精确 70 passed）→ A6
preserved-v1 锚点（精确 55 passed）→ 18 个固定 P1 CPU 节点（精确 18 passed，无 skip/deselect）。

P0 的 **14 项合同自检（`P0/verify.py` 的 `verify_contracts()`）不在本阶段的门内**：它的第 11 项把当前
工作树整份搬进 sandbox 并要求 P0 epoch 基线逐字节通过，而 P1 已声明的 `dispatch.py` 扩展必然违反该断言

证据的期望值是**从固定输入独立重建**的，不是"拿 sidecar 的字段去重算 sidecar 的摘要"（那正是阻断 13 的
问题）。每条运行记录走同一条链路：

1. **请求**由固定切片自己构造（命名实例 → `DispatchRequest.from_instance`），不解析归档里的请求；dispatch
   记录用固定 domain plan / portfolio / evidence 重放（`ExactDispatchResolver`，真实 Metal launch 解析器）。
2. **选中 provider 的投影**从原始固定候选（`tests/support/shape_portfolio_metal.py` 的字节）与
   `DomainAuthority` 重新 `project_provider` 出来，包含子候选 `CandidateArtifact`、manifest、binding、
   `track_id` 与 `identity`；归档 `projection` 必须与它**整份文档**相等。
3. **几何身份**由该投影的执行几何在请求实例自己的 ABI/limits 上重新 `geometry_pair`/`select_geometry`
   求得；`geometry`、`geometry_pair`、`geometry_identity`、`expected_geometry_identity`、dispatch 签名与
   stage 索引都按这份重建值逐字段核对。
4. **构建产物**由 `CanonicalBundle(candidate, pair, lifecycle)` +
   `tcenv.remote.execution_geometry.verify_evaluator_build(report["build"], canonical_bundle=...,
   identity=contract 的 op/降级摘要)` 审计：精确 artifact entries（候选 entries + candidate manifest +
   冻结 `execution_geometry.json`）、唯一 SOURCE 的 path/role/media_type/size/SHA、冻结几何 entry 的字节摘要、
   native entry path/SHA、native descriptor 的 `execution_geometry` 审计、assembled 与 artifact-set digest
   的绑定、以及任务身份。translation unit 另由生产的 `metal_contract(...).assemble(source)` 独立重算
   （assembled SHA、kernel 名、头行数、math 模式、编译设备/GPU family）。`built_entry_paths` /
   `compiled_candidate_sha256` / `artifact_set_digest` / `native_digest` 都取自这次审计。
5. **Host Tiling** 由 `HostTilingPlan.from_candidate(投影候选, 请求合同)` 重新解析：`host_tiling` 文档必须
   整份相等，`host_runs` 的 `path`/`source_sha256`/`plan_sha256`/`writes` 逐次相等，写入量 = `N*4`
   （本切片的 fp32 scratch），执行次数按固定节点的模式（full = correctness + 计时各一次，quick = 一次）。
   workspace 跨度由 ABI 张量算出，清零策略由重建几何算出。
6. **sidecar 语义**整份相等：`evaluation` 文档（provider、runtime provider、fallback 原因、报告
   status/schema/mode/seed、几何路径与原始几何 SHA、`effective_correctness_only`、task pack / locator /
   track / presentation / 评测指纹、lifecycle、`credits_variant`、`evaluation_identity`）与
   `run_identity`（按重建的 `PortfolioRunResult.document()` 计算）必须等于重建值；报告字段
   （task/dtype/size/mode/seed/schema/status/device/backend/协议版本/评测指纹/基线摘要/`pipeline`/`compile.launch`）
   也逐字段独立核对。证据记录与运行组的键集是**闭集**。report_fields/build_fields/record/projection/evaluation
   使用递归严格 JSON 比较：dict/list 逐项递归，标量必须 `type(left) is type(right)`，不再让 Python 的
   `True == 1`、`False == 0.0` 冒充通过。

7. **报告结论由它们的内部证据支撑**，不是`ok` 自说自话：`abi.violations` 必须为空；`safety.ok` 必须恰好等于
   `not violations and not nondeterminism`，且 `validation` 为空；`correctness.ok` 必须恰好等于
   `all(case.ok)`，每个 case 的 `ok` 必须等于 `n_bad == 0`、`n_bad/nan_count/unwritten` 为 0、`safety` 为空、
   `message` 为空、`worst.scaled_err <= allow`、`worst.index` 落在输出张量内、case 名/seed（`7 + 7919*(i+1)`）/
   元素数 = 固定节点与请求实例、tolerance = 请求实例的容差、`coverage.kind="v2-runtime"`、
   `baseline_scaled_err=null` 且 `input_sha256=""`（v2 不跑 v1 baseline/输入复算）；`verification` 必须是
   "unsupported + 无 counterexample + harness 原文"；`message`/`cache_hit`/`compiler_baseline` 是固定节点的值；
   `coverage.scope` 必须是 v2 原文、`worst.index` 必须按 rank 逐维落在输出张量内、`case.scaled_err` 必须等于
   `worst.scaled_err`。case 的 seed/n_elems/n_bad/nan_count/unwritten、worst.index 的每个分量与证据 N
   都先要求非 bool 整数，再做派生值/范围检查，禁止 `int()` 截断或 bool 冒充计数。
8. **计时协议与阶段时间线是语义，不是 volatile**：`benchmark`/`compile` 是闭集，`protocol`/`dispatch` 与 v2 生产
   原文**逐字相等**（保留关键词的否定文案会被拒），`rotation_sets` 由请求 ABI 按生产常量与公式重建，
   `noisy == (noise_cv > NOISY_CV)`、`gpu_lock_wait_s == 0`、`candidate_serial_us`/`candidate_gpu_us_median`
   必须为空、`candidate_us == benchmark.candidate.median_us`、candidate 统计块闭集且 `median_s*1e6 == median_us`、
   `samples_s` 长度 == `reps`；candidate 统计量由生产 `interleaved` 公式从样本重建（median/mean/min/cv/reps/
   median_us 必须与重建的 `BenchStats.to_json()` 相等）、`noise_cv` 等于生产 `attempt_noise`（无 baseline 时即
   候选 cv）、`attempts`/`rotation_sets`/candidate.`iters`/`reps` 都是非 bool 整数，quiet 可在前序 noisy 后停止、
   noisy 时恰为 `BENCH_ATTEMPTS`；**roofline 由生产
   `roofline(task, median_s, 标定资产)` 重建**
   （任务事实 + 实测中位数 + `targets/<id>/calibration.json`，整字典相等）；**worst 证据用固定 case/seed 的
   生产 `prepare_v2_case` 参考输出核对** `worst.want`，并用生产 `scaled_error` 在 `worst.index` 处重算
   `worst.scaled_err`（因此"got 改成 123456 但误差为 0"被拒）；`timeline` 的 (stage, status) 序列按模式固定（quick 五关、full 加 bench，
   全部 ok）、每项闭集、只排除 `duration_s`。correctness-only 报告的 baselines/speedups/baseline_us 必须是
   空 JSON object，空 list 不能靠真值判断蒙混。ABI/correctness/safety/verification/tolerance/coverage/case/
   worst/host 块都是**闭集**。

lifecycle 与其 `cache_scope` 的 `instance_key` 必须等于**请求实例**合同的指纹。live==archived 只在上述
独立语义检查**之后**比较。

无法离线独立重建的原始测量是 `samples_s`、批量选择 `iters`、`elapsed_s` 以及 compile/pipeline/timeline
的墙钟时长；它们必须满足类型与协议边界。`worst.got` **不在**这个集合：固定 exact candidate 的输出可由
case/seed 的生产参考输入离线重建，故 `got == want == reference`，worst 索引也固定为首元素。所有派生结论由生产公式
校验——median/mean/min/cv/median_us 由样本重建、`candidate_us` == median、`noise_cv` == `attempt_noise`、
`noisy` 由 noise 推出、`roofline` 由 task+median+标定资产重建、`worst.scaled_err` == 生产
`scaled_error(got, want, scale, 容差)`、`case.scaled_err == worst.scaled_err`。

`iters` 的检查证明 `kmax`、`iters × min_s ≤ BATCH_WALL_BUDGET_S` 与快/慢路径的 rotation 边界，**不声称**
从最终样本精确重建 `choose_iters` 的近似 `target_s=0.015` 选择。生产用未归档的单次/小批 probe 求 `per`，
正式样本可在此后因频率或负载变化而不同，所以 `iters × min_s ≈ target_s` 不是硬后置条件，不能拿最终
`min_s` 反推一个必定成立的等式或上界。P1 不发布 speedup；这里保留的是可证明的生产不变量，而非伪造的
probe 精确重建。报告里能成为结论或身份的字段都已按上表钉住——`timeline`
不再是整块 volatile，它的 (stage, status) 序列按模式固定、每项闭集、只有 `duration_s` 排除；
`benchmark`/`compile` 是闭集，`protocol`/`dispatch` 与 v2 生产原文逐字相等、`rotation_sets` 由 ABI 重建、
`noisy == (noise_cv > NOISY_CV)`、`candidate_us == benchmark.candidate.median_us`、`measure_serial=false`、
`attempts` 按 noisy 选择规则约束且为非 bool 整数、`gpu_lock_wait_s` 是非 bool 有限数值、`worst.scaled_err == case.scaled_err ≤ allow`、`worst.index` 按 rank/逐维边界落在输出张量内、
`coverage.scope` 是 v2 原文；`build.evidence.log` 的**字节可以逐字节重建**（空结论已删除）：日志正文是生产 `MetalSourceBuilder` 的固定三行模板，
验收器用固定源/合同、报告里的两个时长、A3 附几何前的原生文档（多文件用 `kernel.tx` + 合并源码摘要，单源用候选
条目）重渲染，要求 `size_bytes`、`sha256` 与 `build.evidence.duration_ms = round((compile_s+pipeline_s)*1000)`
全部精确相等。原始测量值本身不能靠离线重算证真；本门证明其类型/边界与全部可派生结论一致，实时重跑
再由 stable live 比较证明固定切片语义没有漂移。

live/archived 的 stable 文档、host 与 refusal 也使用同一递归严格 JSON 比较，设计上的 bool（ok/exact/noisy/
measure_serial 等）仍按 bool 验收，但 bool 不能冒充数值。比较排除的字段是精确的耗时字段（`elapsed_s`/`timeline`/`benchmark` 的测量子字段/`roofline`、
host 步骤的 `duration_ms` 与其日志摘要、`compile` 的计时子结构），以及**由报告（含计时）
派生的三个摘要** `report_digest`/`evaluation_identity`/`run_identity`。这三个摘要不参与跨次相等，但每次
归档都会单独重算校验（见上），所以"只排除计时"不是"排除掉无法验证的东西"。

CPU/GPU 分阶段不可伪造：`--phase cpu` / `--phase gpu` 只是诊断，退出码为 2 并明确打印"未验收"；
只有默认（两阶段都跑）的完整运行才可能返回 0。没有真实 GPU 的机器不可能伪装成 P1 通过。

### 附带：负例框架把"任何异常"都算作拒绝

`verify_forgery_negatives()` 的否定分支只捕获异常并计数，没有断言拒绝**原因**。这意味着如果验收器

### 附带：`--phase cpu` 会打开 Metal 设备
