# 远程评测服务部署与轮换

状态：Phase 2D1 运行手册，2026-10-25。配套协议见
[对外评测服务协议](对外评测服务协议.md)，设计与阶段见
[执行运行时与设备扩展计划](执行运行时与设备扩展-plan.md)。本文描述**单租户、
每设备 single-active、non-HA** 的 v1 部署；多副本、真实站点与真实设备验收另行
立项。真实 GPU/NPU、付费模型和发布加速比不在本文授权范围内。

## 1. 交付物与目录

| 组件 | 位置 | 作用 |
| --- | --- | --- |
| 生产 gRPC 入口 | `python -m tcenv.remote.grpc_service` | TLS/mTLS、每 RPC grant、六 RPC、持久 job/attempt |
| 生产 frontend 镜像 | `deploy/remote-evaluator/Dockerfile` | 非 root、只读 rootfs、无设备；容器执行面需要 frontend 自身能访问 Docker Engine（见 §2.5） |
| worker 镜像 | 由部署方构建/固定 | 每次 attempt 一个一次性容器；非 root、只读 rootfs、无网络、无 bind mount、无 Docker socket、无凭据 |
| 证书/密钥/grant 工具 | `scripts/remote_evaluator_admin.py` | CA、server/client 证书、keyring、grant 文件 |
| 状态运维 | `python -m tcenv.remote.state_admin` | 离线备份、恢复、巡检、隔离释放 |
| host 客户端 | `scripts/remote_evaluator_client.py` | capabilities / submit / conformance |
| Go conformance | `tests/support/remotegrpc/` | 独立非 Python 实现的完整 RPC 流程与摘要/验签 |
| Python 合约/适配器 | `tcenv/remote/{grpc_contract,grpc_server,grpc_client}.py` | 传输无关核心之上的唯一 adapter |
| 任务包校验 | `tcenv/remote/task_pack.py` | 重算 manifest/digest/fingerprint |
| 密钥环 | `tcenv/remote/keyring.py` | HMAC 签名/验签 keyring |

部署目录建议（全部 0600，目录 0700；只有状态卷对容器可写）：

```text
/etc/tcenv/
  tls/ca.pem                # 客户端信任的 server CA（host 侧与 server 各一份）
  tls/server.pem            # SAN = 实际 endpoint hostname
  tls/server.key
  tls/client-ca.pem         # server 验证 host 共享 mTLS identity 的 CA
  grants.json               # 活跃 session grant 的权威集合
  keyring.json              # HMAC 签名/验签 keyring（含 active_key_id）
  task-pack/                # pack.json + fingerprints.json + sources/
/var/lib/tcenv/state/       # SQLite WAL 持久卷，0700，容器 uid 拥有
/var/lib/tcenv/backups/     # 离线备份
```

不要把状态放在 `/tmp`、容器临时层、NFS/CIFS/9p 或共享挂载；不要把 host HOME、
API key、设备节点或 Docker socket 挂进 **worker**。frontend 直接终止 TLS，只开一个
受防火墙 allowlist 保护的监听；GetCapabilities 也必须认证，health 只允许 loopback。

生产默认是容器执行面，因此 **frontend 进程**必须能访问 Docker Engine：推荐直接把
`python -m tcenv.remote.grpc_service` 跑在设备主机上（服务账号在 `docker` 组，状态
目录 0700），或使用装了 Docker CLI 的派生 frontend 镜像并只把 socket 挂给 frontend。
Docker socket 等价 root，frontend 属于受信评测域；worker 容器永远不拿 socket、host
路径或宿主环境。plain Docker + runc 只证明 cgroup/namespace 生命周期，不是不可信
代码的完整安全边界；gVisor/Kata 未实现未验收。

## 2. 首次 provision

1. **CA 与证书**（可为部署 CA 或站点已有 CA；server SAN 必须匹配客户端校验名）：

   ```bash
   python scripts/remote_evaluator_admin.py ca-init --out /srv/tcenv-pki
   python scripts/remote_evaluator_admin.py cert-issue \
     --ca /srv/tcenv-pki --out /etc/tcenv/tls --name evaluator --kind server \
     --san DNS:evaluator.example.internal,IP:10.0.0.10
   python scripts/remote_evaluator_admin.py cert-issue \
     --ca /srv/tcenv-pki --out /etc/tcenv/tls --name control-host --kind client
   ```

   server 与 client 证书、私钥都必须是 0600；`grpc_server.load_server_credentials`
   和 `load_client_credentials` 会拒绝 group/other 可读的密钥材料。客户端校验
   CA、SAN/hostname，禁止 insecure channel。

2. **HMAC keyring**：

   ```bash
   python scripts/remote_evaluator_admin.py keyring-init \
     --out /etc/tcenv/keyring.json --key-id npu-node-01/key-1
   ```

   `active_key_id` 是当前签名 key；host verifier 的 keyring 至少包含当前与历史
   未撤销 key。v1 只支持 host-controlled `hmac-sha256-v1`，不提供公钥签名或
   第三方独立验签。

3. **session grants**（每个 run/session 一个 token；formal/selfcheck 可用不同
   token，但 scope 必须在同一个 grants 文件里）：

   ```bash
   python scripts/remote_evaluator_admin.py grant-mint \
     --out /etc/tcenv/grants.json --append \
     --token-out /srv/host-secrets/run-1-session-1.token \
     --run-id run-1 --session-id session-1 --target-id npu-node-01 \
     --subject control-host --kinds formal_eval,selfcheck --expires-in 86400
   ```

   grants 文件是**权威活跃集合**：启动时不在文件里的活跃 scope 会被撤销，并取消
   其 active attempts。新增一个同 subject/run/session/kind/target 的新 token 会在
   重启时作为续期处理（旧 token 被 supersede，已接受 job 保留）。用
   `grant-mint --append --renew` 可以替换同一 scope 的 token；已被撤销的 scope/token
   不能通过重启重新激活；需要新的 run/session。

4. **任务包**：`task-pack/pack.json` 声明 `schema_version/backend/target_id/
   reference_versions`；`task-pack/fingerprints.json` 声明每个
   `task/dtype/size/fingerprint`；其余文件按排序 POSIX 相对路径进入 manifest。
   服务端重算 manifest、`task_pack_digest` 和每个 fingerprint，任一不一致都
   拒绝启动，不会进入 worker。`pack.json`/`fingerprints.json` 也随任务包哈希。

5. **校验部署输入（不监听、不打开状态库）**：

   ```bash
   python -m tcenv.remote.grpc_service --check \
     --state-dir /var/lib/tcenv/state --site-id npu-node-01 \
     --device-id npu-node-01-dev0 --backend npu --backend-version 1 \
     --target-id npu-node-01 --worker-build build-2026-10-25 \
     --calibration-digest <64 个十六进制字符> \
     --task-pack-root /etc/tcenv/task-pack \
     --grants-file /etc/tcenv/grants.json \
     --signing-keyring-file /etc/tcenv/keyring.json \
     --certificate-file /etc/tcenv/tls/server.pem \
     --private-key-file /etc/tcenv/tls/server.key \
     --client-ca-file /etc/tcenv/tls/client-ca.pem
   ```

   生产入口拒绝 `tests.*` worker module 和 `simulated` measurement identity；
   测试/模拟 composition root 只能存在于 `tests/support/` 制品。

6. **启动**：按 `deploy/remote-evaluator/README.md` 的只读 rootfs、tmpfs、
   `--cap-drop ALL`、`--security-opt no-new-privileges`、`--user` 与两个 bind
   mount 启动；状态卷必须归容器 uid 所有且 0700。

7. **host 配置**（`--remote-evaluator-config` 的 JSON）：

   ```json
   {
     "transport": "grpc",
     "endpoint": "evaluator.example.internal:7443",
     "tls_server_name": "evaluator.example.internal",
     "ca_file": "/etc/taic/tls/ca.pem",
     "client_certificate_file": "/etc/taic/tls/control-host.pem",
     "client_private_key_file": "/etc/taic/tls/control-host.key",
     "token_file": "/etc/taic/grants/{run_id}-{session_id}.token",
     "selfcheck_token_file": "/etc/taic/grants/{run_id}-{session_id}.selfcheck.token",
     "signature_keyring_file": "/etc/taic/keyring.json",
     "target_id": "npu-node-01",
     "task_fingerprint": "<64 hex>",
     "expected_site_id": "npu-node-01",
     "expected_device_id": "npu-node-01-dev0",
     "expected_worker_build": "build-2026-10-25",
     "expected_task_pack_digest": "<64 hex>",
     "publishable_site_ids": ["npu-node-01"],
     "publishable_epochs": ["<capabilities 返回的 evaluator_epoch>"],
     "required_features": ["durable-jobs", "attempt-receipts", "progress"],
     "rpc_timeout_s": 30,
     "watch_slice_s": 30,
     "job_margin_s": 30
   }
   ```

   `publishable_site_ids`/`publishable_epochs` 默认拒绝；模拟站点与模拟 epoch
   永远不能登记。`execution.json` 记录 `transport`、`evaluation_epoch`（观测到的
   `evaluator_epoch`）、`api_contract_id`、`evidence_contract_id`、key id 与
   observed 身份；`evaluation_outbox` 每行记录 transport、API/evidence、attempt
   与签名 key id。resume 时 transport、两类合约和观测身份任一变化都停下，不混算。

## 2.5 worker 执行面：每次 attempt 一个一次性容器

生产外部评测的**数据面执行**不再是一个本地进程组 worker，而是每次 attempt 一个
一次性容器。Docker Engine/containerd 负责进程与 cgroup 生命周期；SSH 只允许做带外
管理，**不是**评测数据面。代码在
`tcenv/remote/{supervisor,container_supervisor}.py`，由 `JobEngine` 通过窄接口
`AttemptSupervisor` 调用；队列、幂等、quota、lease/fence 和结果合约仍是原来唯一的
`JobEngine`，没有第二套实现。

生产入口 `python -m tcenv.remote.grpc_service` 默认 `--worker-execution container`：

```bash
python -m tcenv.remote.grpc_service \
  --state-dir /var/lib/tcenv/state \
  --worker-execution container \
  --worker-image registry.example/tcenv-worker:1.0 \
  --worker-image-digest <64 hex image id> \
  --worker-build 'evaluator-1.0+img:<同一个 64 hex digest>' \
  --worker-python python3 \
  --worker-runtime ''          # 空 = daemon 默认（runc）；gVisor/Kata 见下
  ... # 其余 TLS / grant / keyring / task pack 参数不变
```

- **frontend 需要 Docker 访问**：默认容器模式下 frontend 通过本机 Docker socket
  或 `--docker-host` 调用 Docker Engine，并需要 `docker` CLI。基础镜像
  `deploy/remote-evaluator/Dockerfile` 不含 Docker CLI；推荐 frontend 直接跑在设备
  主机上（服务账号在 `docker` 组），或构建派生镜像后只把 socket 挂给 frontend。
  worker 容器不拿 socket、host HOME/repo、设备节点或长期凭据。
- **镜像按 sha256 镜像 ID 固定**：`--worker-image-digest` 必须是 `docker image
  inspect` 的 ID；每次 `create` 前重新校验，不是目标 digest 就拒绝启动。签名结果的
  `provenance.worker_build` 必须带 `+img:<digest>`（入口会强制），attempt 行还记录
  `container_image_ref/digest/runtime`。换镜像 = 换 build identity，不混算。
- **强制加固参数**：`--init`、`--read-only`、`--cap-drop ALL`、
  `--security-opt no-new-privileges`、`--network none`、`--pids-limit`、
  `--memory`、`--cpus`、数值 `--user`、两个 tmpfs（`/tmp` 与每次 attempt 的
  `/scratch`）。不挂 bind mount、不挂 Docker socket、不传 host 环境；worker env
  只来自显式 `--env-file`（0600，create 后删除），键名含 KEY/TOKEN/SECRET/
  PASSWORD/CREDENTIAL 形状的直接拒绝。候选源码只走私有 stdin 帧，不进 argv。
- **顺序与 daemon 绑定**：`claim` 先持久化 `running + attempt + lease fence +
  execution_kind`，再把 **Docker daemon identity**（`docker info --format '{{.ID}}'`）
  写入 attempt，然后 `docker create`，把 `container_id/name/image/runtime` 写进
  attempt，最后 `docker start --attach` 才写请求字节。前端崩溃时按持久
  `container_id`（create 输出丢失时按确定性容器名 + attempt label）回收，不自动重跑
  running attempt；恢复必须先核对当前 daemon identity 与持久值一致，换成另一个
  daemon 时 fail closed（quarantine），不会把“在 B 上不存在”当成“A 上已清理”。
- **create 失败也不猜**：`docker create` 报错或超时并不等于没创建出容器（CLI 失败
  时 caller 拿不到 id）。此时按确定性容器名 + attempt label 清理并确认不存在，才
  把 attempt 标成可 Retry 的 `worker_unavailable`；清不掉就 quarantine，不放行
  Retry。
- **Cancel/start/请求授权线性化**：Cancel RPC 在 `_active_lock` 内提交持久取消，
  start 前在同一把锁内重读持久 cancel 标记；请求写入另有 `request_lock`，写入授权
  与取消互斥，已取消的 attempt 不会收到候选字节。`kill` 遇到 `created` 容器直接删
  （没有进程可 signal，删掉才能证明并发的 `docker start` 不会让它跑）。Cancel 的
  同步等待是**一个总 deadline**：超过就返回诚实的 `running + cancel_requested`
  （不谎称“已同步 teardown”），由 scheduler 继续完成取消；返回 `cancelled` 时容器
  已删除并验证。
- **停机**：timeout、Cancel、正常退出都走 Kill → Delete → verify；只认 `docker
  inspect`/`docker ps --filter label=...` 的确认结果，不认命令退出码。容器、cgroup
  （`--cgroupns host` 可见时按 host cgroup 路径核对，可用 `cgroup_root` 配置）、
  label 重名容器、attach 客户端、host 侧 env/temp/scratch 任一残留都算 cleanup 未
  完成：不提交 result/receipt，job 置 quarantined 并拒绝 Retry，必须人工
  `state_admin`/`release_quarantine` 复核。create 时 env 文件删不掉、create-time
  SIGKILL 留下的 env 文件、删不掉的 scratch 目录同样算未完成（恢复时清理并复验）。
  `docker inspect` 给出 exited 但没有 exit code、或 deadline 时状态不是 running
  （absent/created/unknown）时按 supervisor 失败处理，不降级成候选 timeout。
- **结果提交前必须完整校验**：stdout reader 必须读到 EOF 并跑完
  `decoder.finish()`；已知的畸形报告（错 task/seed/evidence、第二条 result）优先于
  timeout 判定；reader 未结束不提交任何结果。
- **CLI 输出流式有界**：Docker CLI 的 stdout/stderr 按固定块读取并设上限，超限直接
  杀掉 helper 进程，不在内存里无限缓冲。
- **旧 fence 不能提交**：结果仍由 `complete_attempt` 校验 running + attempt_id +
  lease fence；已取消/已删除容器的迟到帧不会变成结果。
- **跨 build / 跨执行面 / 跨 epoch 的旧队列不执行**：queued job 的持久 `expected`
  身份（site/device/target、worker_build、task pack digest、evaluator epoch、
  API/evidence contract）与持久 provenance 必须与当前 frontend **完全一致**，否则
  fail closed（interrupted + quarantine，不创建容器）；只比 `+img:` 后缀不够（build
  A→B、同镜像不同 epoch 都会漏）。生产组合根还直接拒绝“进程执行 + `+img:` 的
  worker_build”，local 进程执行也不能冒充镜像。
- **进程 attempt 没有持久 PID 就不算干净**：spawn 与 PID/start-token attach 之间被
  SIGKILL 时没有可证明死亡的身份，stdin EOF 不等于进程已死；恢复/运维释放都必须
  fail closed（quarantine），不能直接给 Retry。start-token 取不到且清理未确认时同样
  quarantine。
- **旧 recovery 不能碰新 attempt**：`recovered_attempt` 只在 job 仍 running、当前
  attempt 恰好是它恢复的那个 attempt/fence、且该行仍 running 时写入；延迟的 A 写入
  不能把正在跑的 B 标成 interrupted。
- **v1/v2 备份仍可恢复**：schema v3（新增 daemon identity）由 v1/v2 就地迁移；
  `JobStore.restore_backup` 接受 v1/v2/当前版本，恢复后正常 open 迁移，历史签名结果
  （含 key 轮换后仍可信的旧 key）与队列/结果保留。
- **worker 仍跑现有私有协议**：容器内是
  `tcenv.remote.legacy_worker_bridge` + 生产 `tcenv.remote.worker`（或镜像内的等价
  入口）；对外 gRPC/TLS/Protobuf 六 RPC、grant、HMAC 全部不变。
- **local 默认不变**：`LocalEvaluator`、本地 agent、Unix-socket selfcheck bridge
  和 `--worker-execution process` 的本地开发路径都保留；进程模式必须显式
  `--worker-execution process --allow-process-worker`，生产入口默认拒绝，两者之间
  没有静默回退。Phase 3 的可选 SSH workspace transport 与本执行面无关，它既不是
  生产评测数据面，也没有因为这次工作修好 SSH 超时问题。

**运行时档位（尚未实现/验收）**：`--worker-runtime-profile runc|gvisor|kata` 与
`--worker-runtime <oci runtime>` 只是记录/透传字段。plain Docker + runc 证明的是
cgroup/namespace 生命周期，**不是**针对不可信代码的完整安全边界；gVisor（`runsc`）
与 Kata 需要设备侧实际安装、配置和单独验收，当前没有实现也没有跑过，不能声称已
支持或已验证。部署时请把 worker 镜像与 Docker Engine 当受信评测域的一部分维护，
并给 worker 专用节点/账号，不与不可信内循环共用。

## 3. 轮换与撤销

| 对象 | 正常轮换 | 安全撤销 | 对 epoch/已有 job 的影响 |
| --- | --- | --- | --- |
| server TLS 证书 | 新 SAN 证书先部署到 frontend，再更新 host CA/客户端信任；旧证书保留到过期 | 从信任链/allowlist 删除，重启或拒绝旧身份 | 不改变测量 epoch；已接受 job 继续由持久状态服务 |
| host mTLS client 证书 | 同一 CA 签发新 client 证书，host 先换文件 | 撤销 = 把该叶子证书 DER 的 SHA-256 写入 0600 的 `revoked-client-certs.json`（`--revoked-client-certificates`）并重启 frontend；每个 RPC 在授权 grant 前比对，命中即 `PERMISSION_DENIED`。这是 TLS 栈无 CRL/OCSP 时的静态逐证书撤销表，不从网络抓取 CRL/OCSP | 撤销前的 active job 仍由服务端取消/审计；不能让已撤销身份继续读 |
| HMAC keyring | `keyring-rotate` 生成新 active key，旧 key 保留；host keyring 同步包含新旧；重启 frontend | `keyring-revoke` 立即从可信 keyring 删除；旧结果验签失败 | 正常轮换不改变 epoch；撤销 key 后相关结果只能作诊断，不能发布 |
| grants | 同 scope 新 token 写入 grants 文件并重启（自动 supersede 旧 token）；已接受 job 保留 | 从 grants 文件删除 token 并重启：scope 撤销、关联 active attempts 取消；不能恢复被撤销 scope | 不改变 epoch；撤销不能靠旧 token 调 Cancel，必须由服务端取消 |
| API/evidence contract | 新增可选 feature 必须经 required_features 协商；breaking change 开 v2 | 不支持合约直接拒绝 | 变更 API/evidence contract 不强制新测量基线，但新 run 必须固定新 ID；跨合约不能回放 |

轮换的验收命令：

```bash
python scripts/remote_evaluator_admin.py keyring-rotate --file /etc/tcenv/keyring.json --key-id npu-node-01/key-2
python scripts/remote_evaluator_admin.py keyring-revoke --file /etc/tcenv/keyring.json \
  --key-id npu-node-01/key-1 --new-active npu-node-01/key-2
python scripts/remote_evaluator_admin.py keyring-show --file /etc/tcenv/keyring.json
```

逐证书撤销文件与 keyring 一样是 0600、重启加载、不改变 epoch：

```json
{"schema_version": 1,
 "revoked_client_certificates_sha256": ["<leaf DER 的 64 位小写 hex>"]}
```

指纹必须来自 TLS 已经认证的叶子证书；文件格式错误或权限不严会让 frontend 拒绝启动。
`revoked-client-certs.json` 为空表示不额外撤销，TLS 的 CA 校验仍然生效。

正常轮换后，旧结果必须仍能用旧 key 验证（host keyring 保留旧 key）；撤销后
旧 key 缺失，服务端把受影响结果隔离并扣留，但 frontend 仍可启动；host outbox
也不会重放该 completed 结果（只记录 `signature_key_revoked`）。轮换脚本不打印
key 或 token。

**时钟**：grant/capability 过期、retention 和持久 deadline 以服务端时间为准；
`--clock-skew-ms`（默认 5000，范围 0..300000）只放宽临期接受窗口，不放宽撤销、
generation 或 API/evidence 绑定。运行时超时用 monotonic clock，落盘用 UTC。

## 4. 备份、恢复与迁移

### 4.1 备份

frontend 的 SQLite 是单写者 WAL 库，备份必须离线：

```bash
# 先停止 frontend（docker stop / systemctl stop），确认进程退出
python -m tcenv.remote.state_admin backup \
  --state-dir /var/lib/tcenv/state \
  --out /var/lib/tcenv/backups/state-$(date +%Y%m%dT%H%M%S).sqlite3 \
  --keyring-file /etc/tcenv/keyring.json
```

备份使用 SQLite online backup 并做 `PRAGMA integrity_check`，输出 0600。RPO 是
最近一次成功备份加上已 fsync 的 WAL；站点/磁盘丢失的 RPO 由备份周期决定。
non-HA 不承诺零丢失或自动故障转移。备份必须同时保留当时的 keyring（至少包含
历史未撤销 key），否则恢复时已签名结果会被拒绝。

### 4.2 恢复

```bash
python -m tcenv.remote.state_admin restore \
  --backup /var/lib/tcenv/backups/state-....sqlite3 \
  --state-dir /var/lib/tcenv/state-restored
python -m tcenv.remote.state_admin inspect \
  --state-dir /var/lib/tcenv/state-restored --keyring-file /etc/tcenv/keyring.json
```

恢复要求目标目录为空；恢复后写入 `restored.marker`，**所有非终态 job 先隔离**，
不会自动重跑。逐条检查 `quarantined` 的 attempt/worker/lease 后，才可：

```bash
python -m tcenv.remote.state_admin release-quarantine \
  --state-dir /var/lib/tcenv/state-restored --keyring-file /etc/tcenv/keyring.json \
  --request-id <request-id>
```

release 不授予“忘了旧 worker”的权限：如果旧 worker/lease 不能确认清理，仍然
拒绝启动新 attempt。RTO 包含停服、恢复、隔离检查和设备健康检查；rollback 必须
使用能读懂当前 store schema 的二进制，不能靠删除状态“恢复”。

### 4.3 从 `legacy-ssh` 迁移

- 历史 `legacy-ssh` run 继续由 `RemoteEvaluatorPool` 按各自固定协议 resume；
  不要在同一 run 中混用 transport。新 run 使用 `transport=grpc`。
- 旧 `execution.json` 缺少 `transport` 时按 `legacy-ssh` 解释；gRPC run 的
  `execution.json` 必须有 `api_contract_id`/`evidence_contract_id`，缺一不可
  resume。`evaluation=local` 不变。
- 旧 `legacy-ssh` 服务把 formal/selfcheck 当两个独立 frontend；它们的 SQLite
  存储不能共享。`RemoteEvaluationConfig.command` 的状态路径应包含
  `{evaluation_kind}`（例如 `--state-dir .../{evaluation_kind}/{session_id}`）；
  两个进程指向同一 store 时第二个会因单写者 owner lock 启动失败（fail closed）。
- 旧 per-request JSON 只读兼容：completed/failed/running/corrupt 行由
  `RemoteService` 显式处理；`selfcheck_usage.json` 无法无损导入，启动时拒绝，
  必须人工导出/删除后再开新存储，不能静默清零配额。
- gRPC 前端使用一份持久 job store 同时服务 formal/selfcheck；不要启动两个
  frontend 指向同一状态卷（`owner.lock` 会拒绝）。

## 5. 失败、回滚与运维检查

- **Submit 结果不明**：GetJob 对账；确认未接受才在同一 request_id/digest 下重提；
  已接受但 interrupted 用显式 Retry，不自动重跑。Retry 需要新的 capability。
- **取消**：Cancel 幂等；最终状态由 GetJob/Watch 确认；关闭 Watch/断网不等于取消。
- **旧 worker/lease**：重启先清理/隔离；未确认旧 worker 死亡前不启动新 attempt。
- **回滚**：先停止新 Submit/Retry，drain 或显式 Cancel，核对 attempt/终态、旧
  fence、worker 和租约清理；保留已完成证据与 outbox；服务端二进制回滚必须仍能
  读当前 store schema（`python -m tcenv.remote.state_admin inspect` 可校验）。
- **健康检查**：GetCapabilities 走 mTLS+grant；`--check` 只校验文件/任务包，
  不监听。健康探针不要绕过认证。
- **日志**：默认只记录 request/attempt/digest/状态与必要错误，不记录源码、
  token、私钥、完整任务定义或 host 路径；调试原文需单独开启并有期限。
- **数据生命周期**：终态后删除原始源码/临时目录；report/evidence/receipt 默认
  保留 30 天，不短于 host resume 保留期；tombstone 覆盖结果保留期。崩溃转储、
  备份与日志归档使用同一清理策略。
