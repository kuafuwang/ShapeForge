# 先读这一页

模型负责写显卡小程序的文字。本仓库的程序负责编译、查安全、对答案、计时，并决定留哪一版。模型看不见显卡，也不能自己宣布写对了或更快了。

能对外说的倍数，要等搜索结束，换一批输入再测，源码对得上，计时也不吵。搜索过程里看起来最快的那次，是另一个数。权威记录在 `runs/` 里该次搜索的 `result.json`，还要过 `experiments/common.py` 的 `conclusion_of_run`。下面各篇里的对照表是写作时的快照。

默认一次新搜索大约 15 美元（预设名叫 `paper`）。两个模型轮流写：DeepSeek 的 `deepseek-flash`，然后是月之暗面的 `kimi-k3`。只配一家的密钥不够。`--preset base` 才读 `taic.toml` 自己的上限，那是 50 美元。`taic run` 和 `taic resume` 会花钱，也会把程序交给这台同时画屏幕的显卡。只看摘要用：

```
uv run python -m taic.cli brief
uv run python -m taic.cli brief RUN_DIR
```

每一轮都是一场新的 `hmz` 会话。写错了，评测不合格的反馈写进下一场任务书，不留在同一段对话里，也不另发规划请求。两个委员会仍轮流。模型相同也换一场。

## 这几句是常识

| 词 | 在这个仓库里指什么 |
| --- | --- |
| 题目 | 一份 Triton 文本，加上标准答案、现成库和允许的误差。主环境不拿 Triton 来编译 |
| 内核 | 要交给苹果显卡的那份 Metal 小程序 |
| 评测（`tcenv`） | 编译、查接口、对答案、计时。它不写程序 |
| 搜索（`taic`） | 安排模型写、看成绩、只留下又安全、抽查算对、而且明显更快的一版 |
| 种子 | 下一轮接着改的那一版合格程序 |
| 确认 | 搜索结束后的复测。对外倍数来自这里 |
| 上界 | 用这道题的运算量和这台机器测到的峰值，估一个「按当前算法最快大概多久」。它不是物理极限 |

算对是抽查，不是证明。留下的那一版可以比现成库更慢。死循环仍可能把电脑冻住。这些边界写在 [诚实说明.md](诚实说明.md)。
