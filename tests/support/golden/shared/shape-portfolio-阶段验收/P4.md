# P4：清微 NPU 离线数据与协议模拟

状态：**completed**。这是 Mac 侧 shape portfolio 的离线 NPU 边界。NPU-P0 仍是 `blocked`。

## 做了什么

有限域题 `portfolio_pointwise` 仍由候选 envelope 声明 coverage。Harness 用 P0 的语义域、投影身份和 exact resolver 选唯一 provider：

| size | N | provider | variant |
| --- | --- | --- | --- |
| tail | 7 | candidate | `variant-c-tail` |
| below | 63 | fallback | 域内未覆盖，`outside_candidate_coverage` |
| threshold | 64 | candidate | `variant-a-bundle` |
| above | 65 | candidate | `variant-a-bundle` |
| large | 1024 | candidate | `variant-b-single` |

`golden` 和 `benchmark` 都走同一选择。域外点和自相矛盾的请求停在 `unsupported_contract_capability` / `semantic_unresolved`，不落到 fallback，也不提交协议。

选中的投影绑定按现有合同提交：

- source：fake vendor A，`tcenv.remote.npu-source.evaluator-api.1`
- bundle：fake vendor B 的 `GRAPH_DEFINITION` + `PARAMETER_TABLE`，`tcenv.remote.npu-bundle.evaluator-api.1`

协议夹具任务仍是 preserved v1 `sem_attention_odd_scale`。它只认证提交字节，不表示 `portfolio_pointwise` 在 NPU 上执行。receipt 的 candidate digest 分别等于提交字节的 sha256 和 artifact set digest。

P2 的隔离和 manifest 负例用在同一份 portfolio 上：`large` 是 tune，其余 8 个点是 required unseen；候选视图只有 tune keys。文档态 manifest 用 P2 的 subject 字段通过校验，其中 `coverage_kind` 只是这套字段要求的名字，`stable_confirmation_digest` 不是 fresh confirmation。状态保持 `validated` / generation 0，激活被拒绝。伪造 manifest digest、fallback 记成 variant、外来 `variant_id` 都被拒绝。bundle payload 改一个字节也被拒绝。

## 证据边界

`P4/evidence/simulation.json` 固定 `simulated=true`、`publication_allowed=false`、`npu_p0.status=blocked`。假服务回传的 `timing`、`candidate_us`、`elapsed_s` 和 `speedup` 只记在 `omitted_protocol_fields`，不进入报告。这里没有真机 correctness、性能或发布结论。

proto、六 RPC、field number、HMAC、BlobChannel 和 remote EvalReport 都没有改。
