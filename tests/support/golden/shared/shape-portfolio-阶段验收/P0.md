## 3. 合同要点

### 3.1 有限语义域

`normalize_semantic_domain_plan(spec, instances, target=...)` 把显式命名的 `SemanticInstanceV2`
展开为 `(dtype, size, usage)` 点：OpSpec 声明的每个 usage 都是独立点，`golden` 与 `benchmark`
不混用。每个点记录 `semantic_instance_digest`（实例完整投影的 fingerprint）与
`target_abi_digest`（派生 ABI 的指纹）；计划记录 `opspec_digest` 与 `target_generation_digest`
（目标档案 + 后端版本 + 上限）。instance 顺序按 `(dtype,size,usage)` 规范化，摘要不依赖作者顺序。

拒绝路径：

- `domain_kind=non_finite` → `UnsupportedContractCapability`（normalize 与 parse 都拒绝）；
- 未登记 kind → `TaskContractError`；
- 外来 OpSpec 的实例（dtype/size 拼写相同也不行）→ `UnsupportedContractCapability`；
- 重复点、空点集、非法 instance_key → `TaskContractError`。

### 3.2 Guard canonical AST

`canonical_ast` 在 `expr.Node` 上工作：`gt(a,b)→lt(b,a)`、`ge(a,b)→le(b,a)`；`and/or` 递归规范化后
扁平化并按 canonical JSON 字节排序；`{eq, ne, +, *, min, max}` 的交换操作数按 canonical bytes 排序
（`-`、`/`、`trunc_div`、`rem` 与比较保持作者顺序）。`CanonicalGuard.digest` 只哈希
`{"call","args"}` 形式的规范 AST，绝不哈希原始字符串；`parse_guard` 要求声明的 digest **必须**等于
重新计算的规范摘要，因此“原始字符串摘要”“换一种写法的摘要”都会被拒绝。

workspace 是**权威 OpSpec 的事实**：`project_provider` 接收与 portfolio/domain 绑定的
`DomainAuthority`（计划必须由权威 OpSpec/target/instances 重算），由它判定
`workspace_declared`；调用方不再传入布尔值，也不能用另一个域的 authority。因此“有几何但 OpSpec 无
workspace”在投影期被拒绝，而不是被声明成 bundle。

固定 golden（同义写法应相等、不同语义应不同）：

| 表达式 | digest |
| --- | --- |
| `gt(N,63)` / `lt(63,N)` | `d01c11ab2cab72b80a7bc49344a0322273c163a18a502a65de08d23fbb65e891` |
| `and(ge(N,64),lt(N,128))` / `and(lt(N,128),le(64,N))` | `3392438f51ac37993df43e217d5bafbda14ff095e03282fbc4e273f2e4399992` |
| `or(eq(N,7),and(lt(N,32),ne(M,0)))` 的两种排序/嵌套 | `f9eacfdc56608972950e1640d9fff497d0943eeea7125e32b447701fb5f45de6` |
| `lt(N-63,0)`（不得改写成 `lt(63,N)`） | `af8707cdf8369f4980d659ae263f745c5bb240c47755a5457c5b516c5688348d` |
| `eq(rem(N,2),1)` / `eq(1,rem(N,2))` | `9043507433934df5f01ec73d2feca30267f44b3f13e930bd804d805f1be986b2` |

### 3.3 候选投影

外层 envelope 的固定 entry 是 `coverage_plan/portfolio.json`（role `launch`：一个没有任何
TrackSpec 为源登记的候选角色名，所以母包**不可能**通过 `validate_for`）。envelope 字段闭集：
`schema_id`、`domain_plan_digest`、`planner`、`coverage_plan.buckets`、`variants`、可选 `fallback`。
bucket 声明的 `guard_digest` 必须等于其成员 variant 的规范 guard 摘要；未知 bucket、重复
`variant_key`、伪造/非规范 digest 均拒绝。

投影规则（`project_provider`）：

| 交付内容 | 结果 |
| --- | --- |
| 有 `geometry_entry` + 恰好一个 `host_tiling` + ≥1 device + OpSpec 声明 workspace | `msl-bundle`；几何映射为固定 `host/execution_geometry.json`（role `schedule`） |
| 无 `geometry_entry` + 恰好一个自包含 device entry（源内自带 `taic-launch`） | `msl-single` |
| 多源/多 host/有几何但无 Host Tiling/权威 OpSpec 无 workspace/缺 launch | 拒绝 |
| 声明 entry 缺失、`#include` 非 `<metal_...>`（引号 include/角括号宿主路径/裸路径）、非 UTF-8 源、非法角色 | 拒绝 |

共享源由每个需要它的 provider 在 `entries` 里声明，投影逐字节复制（不会被缩成“只拷主源”）。
`#include` 只允许 Metal 标准头 `<metal_...>`，与既有 `screen_v2_source` 完全一致：引号 include、
角括号宿主路径、裸路径都在投影期拒绝。`msl-bundle` 的 Host Tiling 不是“role 对即可”：投影复用既有
`HostTilingPlan.from_candidate` 闭集校验（JSON、字段、workspace 名与 dtype 来自权威 TaskContract），
非 JSON、未知字段、未知 workspace、dtype 不符都拒绝。
`taic-launch` 的结构由后端 launch 扫描（`unique_launch_block`，与 `parse_launch_spec` 同一
`_scan`）判定：标记必须**恰好一次**出现在块注释中；行注释、字符串、第二个块、块首不是标记的注释
都不算 launch，投影期立即拒绝。投影后 device 源集合里至少有一个真实 launch 块（`msl-single` 要求
就是那唯一源自身）；只被 include 的共享头文件不因为自身没有 launch 块而被伪造一个，也不会被投影
删掉。
除指定 `geometry_entry`（映射路径/角色/媒体类型固定）外，所有 entries 的 path/role/media_type/bytes
与父 bundle 完全一致；同一投影内路径冲突、两个 provider 重复声明同一 geometry、`geometry_entry`
缺失/角色非 `host_tiling`/媒体类型非 JSON 都拒绝。`EvaluationBinding` 记录 `provider`、variant/
fallback 身份、domain/portfolio 身份、父 bundle SHA、子 `candidate_sha256`、track、原 geometry
路径与内容 SHA-256、映射路径与投影 entry 清单；子 SHA 等于父 SHA 直接拒绝。

`variant_id` 只含 domain plan、planner 身份、规范 guard、声明 entries 的 path/role/media_type/sha、
geometry 声明（原路径+sha）；不含 `variant_key`（诊断名）、作者/会话、测量结果或实例解析几何。
fallback 使用独立的 `fallback_id`，注册角色固定为 `domain_fallback`，与 `timing_baseline` 分开；
`refuse` fallback 不得携带 entries/几何/实现身份，也不会被投影。

### 3.4 Exact dispatch

`ExactDispatchResolver` 顺序固定，运行期逐个求值**全部** guard：

| 条件 | `outcome` | provider |
| --- | --- | --- |
| 请求不可解析（开放字段/类型/usage 非法），或请求字段/语义/ABI 与权威实例矛盾 | `semantic_unresolved` | — |
| 请求是完整实例但不在有限域点集 | `unsupported_contract_capability` | —（永不 fallback） |
| guard 引用未声明字段、求值异常（如 `rem(N,0)`）、命中者证据非 validated | `dispatch_unknown` | — |
| 多个 guard 为真 | `dispatch_overlap` | —（不按优先级猜） |
| 恰好一个 | `resolved` | `candidate` |
| 零匹配且 fallback 声明并验证了 `outside_candidate_coverage` | `fallback` | `fallback` |
| 零匹配但 fallback 缺失/未声明该原因/明确 `refuse` | `dispatch_unmatched` | — |
| 命中 variant 的资源预检超限且 fallback 未声明 `resource_unavailable`；几何非法；fallback 自身不可用（不再链式回退） | `variant_unavailable` | — |

原因由执行阶段派生：所有 guard 为假固定 `outside_candidate_coverage`；恰好一个命中后必须先做
`resolve_geometry(... instance, contract, limits)` 的纯 CPU 预检，超 `TargetAbiLimits` 固定
`resource_unavailable`；`invalid` 几何不会触发 fallback。`preflight_geometry` 将 A2 resolver 的
“exceeds the target limit” 归类为资源超限（测试固定这一措辞协议），其余几何错误为候选缺陷。
单文件来源没有显式几何，预检状态为 `not_required`。

有限域注册期 `registration_report` 枚举全部域点，报告 overlap、空 variant、不可判定 guard；
它只是**有限点集查重**（`coverage_kind=exhaustive_finite_point_check`），不构成静态互斥/终止证明，
也不产生 active 证据。运行期仍全量求值 guard。

域计划本身不是自证的：resolver 与注册检查都要求计划等于用权威
`OpSpec/target/instances`（含 `max_buffer_length`）重算出的规范化计划，否则在构造期以
`TaskContractError` 拒绝；伪造 `opspec_digest`、`target_generation_digest` 或逐点 ABI 摘要后重新
绑定 portfolio 也不能进入 dispatch。

组合记录类型为 `PortfolioDispatchRecord`（`tcenv.portfolio.dispatch-record.1`），与
`v2_runtime.DispatchRecord` 不重名、不混用；记录含请求、全部 guard 结果、matched variant、派生
原因、最终 provider、证据状态与预检状态，不含速度/激活/发布字段。
