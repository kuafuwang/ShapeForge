## 与 B1 不同的三处语义

**1. conv2d 的 IEEE 注入上限随 shape 变化。**
v1 的 `cases.inputs.ieee._max` 是表达式：`x → max(8, N*OH*OW // 100)`，`w → 4`。
冻结证据显示 paper 为 `x=933`、small 为 `x=10`，与公式一致。`reference.py` 因此**从
`instance.symbols` 重算**，而不是把某个档位的数字写死。

**2. conv2d 的参考实现有两条路径。**
有限输入走 `F.conv2d`；含 NaN/Inf 时逐 tap 求和——CPU 的 Winograd 变换会把一个 Inf 抹成
整片 NaN，而 IEEE 语义应该是乘积之和。这条非有限路径在 `ieee` 算例上被逐字节验证。

**3. lion 有模块级 `error_scale` 和三个 baseline。**
`sign` 的间断点放宽（`discontinuity_rel=1e-5`、`atol_steps=2.5`）以 v2 的
`error_scale(inputs, reference_outputs, instance, tolerances)` 钩子实现。
v1 是在 `ieee` 算例上先过滤非有限值再调钩子；v2 的钩子拿不到 case，所以**过滤放进钩子内部**
（对有限算例是无操作）。三个 baseline 中 `mx.compile` 与 `torch.compile` 的融合变体都在
`baselines.py` 里按 v1 的调用形式保留，编译结果按 key 缓存一次。

## 等价性证据

流程与 B1 相同：先用 v1 的 `prepare_case` 冻结 8 组合 × 18 记录（144 条），再让 v2 合同重放。
本批冻结额外记录了 `evaluation_domain`（`ieee_max` 的物化值），供迁移时核对而不是重推。

| 组合 | 输入逐字节 | 参考逐字节 | 尺度逐字节 |
| --- | --- | --- | --- |
| conv2d ×4 | 36/36 | 18/18 | 18/18 |
| lion ×4 | 54/54（p/g/m 三输入） | 36/36（p_out/m_out 两输出） | 36/36 |

`evidence/compare-report.json`：全部逐字节一致。

## 真机切片（GPU）

`tests/backends/metal/test_task_migration_b2_gpu.py`，2 passed：
conv2d 与 lion 的归档 naive 候选在真实 v2 `evaluate_task` 上编译、ABI、正确性、计时全过，
dispatch 与 v1 的 grid/threads 一致，证据写入 `evidence/gpu-*.json`。

切片暴露了一条重要的边界规则：`M_TOTAL`/`K_TOTAL` 是 v1 `LoweringProfile` 的**派生量**，
不是 OpSpec 符号，所以 v2 合同头**不**提供它们——候选必须自己声明。
这正是"候选拥有派生标量"的语义，不是遗漏。

## v1 机制测试的样本夹具（本批新增的基础设施）

B1 把样本从 rope 换成 conv2d 还能成立；B2 之后 v1 **没有任何 elementwise 活题**，
而硬件特征测试的断言恰恰按家族（elementwise/compute）区分。换题会改变断言语义，
所以本批新增 `tests/support/v1_specimen.py`：

- 从迁移证据重建 v1 任务**形状**：核名、常量表、`render_header()`、`describe()`、
  `abi_stub()`、参数表、容差、`flops`/`min_bytes`、归档 naive 候选文本；
- 只覆盖机制测试真正读取的属性（`hw.build_report` 需要 `contract.constants`/
  `kernel_name`/`render_header()`，`taic.prompts` 需要 `describe()`/`abi_stub()`/args/容差）；
- 保留题仍走真实装配（`v1_tasks.v1_task`），夹具只用于已经迁走的样本题；
- 常量存**纯数值文本**（分析代码会 `int()`/`float()` 解析），`u`/`f` 后缀只在渲染时补；
- 预算类测试对契约长度敏感，`describe()`/`abi_stub()` 使用从旧提交直接取出的真实 v1 文本
  （`tests/support/golden/shared/v1-contract-text.json`），不用缩写的近似文本。

`test_hw_feedback.py` 的 `block()` 现在按名字分派：`lion`/`conv2d` 走夹具，
`flash_attention` 等保留题走真实装配。B3/B4 可复用同一套。

lion 的两个 IEEE 行为测试（丢 NaN 被拒、依赖输出初值被判 unsafe）也改走真实 v2
`evaluate_task`：v2 的 `quick` 模式默认**不含** ieee 用例，必须显式给出完整 case 表，
否则这两个测试会假性通过——迁移评测类测试时这是最容易漏掉的一点。
