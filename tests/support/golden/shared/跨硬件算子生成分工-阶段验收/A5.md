## 6. 本轮真实回归的根因与修复

### 6.1 remote TLS / Go conformance：fingerprint 夹具身份不一致

`test_remote_grpc_tls.py` 直接构造 `EvaluationRequest(task="relu", ...)`，而 A5 把共享夹具
`tests/support/job_engine.py` 的 `TASK_FINGERPRINT` 绑定改成了保留下来的 v1 题
（`V1_TASK="rope"`，因为 fake worker 会真的 `get_task` 装配它）。服务端
`ServiceIdentity.accepts_task("relu", ...)` 因此拒绝：`failed_precondition: task fingerprint does
not match the deployed task pack`。Go conformance 的 `--task relu` 是同一个根因。

修复：两个测试从 `tests.support.v1_tasks` 取 `V1_TASK`，与 fingerprint 的 binding 使用同一个
题名。**没有跳过 fingerprint 校验**，也没有把 binding 退回 flat set：`verify_v1_fixture_boundary`
反向断言同一 fingerprint 对迁移题仍然被拒绝。

### 6.2 三个 Go golden：测试夹具误改，不是生产回归

A5 把 `tests/support/remote_contract.py` 的冻结向量题名从 `"relu"` 改成了 `V1_TASK`，但冻结文件
`npu_blob_v3.json`/`npu_bundle_v4.json`/`npu_build_v5.json` 仍按 R4/R6 冻结为 `"relu"`；同时
`schema4_report_payload` 会对题名调用 `get_task`，迁移后 `relu` 已不能在 v1 装配。于是“当前输出
≠ 冻结向量”，但生产 RPC/字段/HMAC/canonicalization 没有任何变化。

判定：这是**测试夹具误改**（把冻结的 wire 数据当成 live 题装配）。冻结向量是跨语言协议证据，
它的题名是数据，不是 task registry 查找；迁移题不应让向量内容变化。修复：

- 恢复 `GOLDEN_TASK = "relu"`（冻结向量的 wire 值），并用
  `frozen_golden_task()` 这个只带 `kernel_contract.kernel_name` + `opspec_digest` +
  `lowering_profile_digest` 的冻结数据对象投影报告；它不是 `tcenv.task.Task`，不装配任何题，
  也不是第二 registry。
- 四个向量（含 `evaluator_v1.json` 的 R4 重建路径）在 `verify_frozen_vectors()` 与
  `test_a5_the_frozen_cross_language_vectors_do_not_depend_on_a_live_task` 下**逐字段等于冻结文件**；
  **没有覆盖 golden、没有删除字段、没有放宽相等断言**。
- 六 RPC/field number/HMAC/BlobChannel/schema 4/发布门未改（`tests/support/remote_contract.py` 的
  变化只在报告身份、题名常量和文档字符串）。

### 6.3 observe 长文件名：生产路径处理缺陷

`test_the_panels_keep_the_byte_budget_with_long_text_and_many_epochs` 用一个 499 字符的题名
`synthetic_confirmation_documents` → `confirmation_expected_document` → `get_task`。
`tasks._task_dir_candidates` 直接拼 `tasks/<name>/opspec.json` 并 `stat`，超长组件抛
`OSError: [Errno 63] File name too long`，既不是“未知题”也不是可读的合同拒绝；带 `/` 的名字还会
探到 `tasks/` 外。

修复（`tasks/__init__.py`）：题名必须是单层、长度 <= `NAME_MAX`、匹配
`[A-Za-z0-9][A-Za-z0-9_.-]*` 的目录名；不合法或超长直接没有目录候选，`get_task` 以普通
`KeyError` 结束；探测本身也包住 `OSError`。这同时修掉路径逃逸面。测试未改、未删；
`test_a5_an_invalid_task_name_is_a_lookup_miss_not_a_filesystem_error` 固定超长、
`../escape`、`/etc/passwd`、`..`、空串与 `gen_` 超长六种输入。
