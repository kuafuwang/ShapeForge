## 闭包约束：哪些符号必须保留为 stub

任务 pack 闭包（`code_import_closure`，worker 部署代码集）里有几个文件仍在调用 v1 入口，
而它们在 `shape-portfolio` 的冻结证据代码闭包内——改一个字节都会让 `task_pack_digest`
与历史验收证据（P2 的 fresh-seed 派生）对不上。因此：

| 符号 | 处理 | 原因 |
| --- | --- | --- |
| `tasks.get_task` / `list_tasks` | **保留为拒绝 stub**（拒绝一切 v2 题，无活题可装） | 闭包内 `tcenv/evaluation.py`/`tcenv/evaluate.py` 仍 `from tasks import get_task`；符号不能消失，只能拒绝 |
| `tcenv/lowering.py`（`LoweringProfile` 基类/注册表） | **保留** | 在闭包内；删除会漂移 P2 证据 |
| `tcenv/evaluation.py` / `tcenv/evaluate.py` | **保留，不改动** | 在闭包内；v1 评测机制靠 specimen 注入维持，而非删除 |
| `metal/lowering.py` | **保留空壳** | A6 的公开 `import *` 锚点依赖它存在；注册内容已全删 |

「删除 `tasks.get_task`」在本批的准确含义是**删除其装配功能**（实现文件与活题装配路径），
而不是删除这个符号本身——符号作为「v1 已退役」的拒绝入口保留，是闭包约束下的必然结果。

## 与历史阶段锚点的关系

`test_lowering_registry.py`（P1 verify 引用）已在更早的迁移中删除，`test_variant_family.py`
在本批删除。这些 P0/P1 的 verify.py 是**当时代码快照**的验收记录，本就不保证在 v1 装配
删除后的新代码上重跑；本批不改动这些历史 verify 脚本的内容（closed boundary），只是它们
引用的 v1 测试文件随 v1 机制一并退役。
