# A2 阶段验收：候选交付、typed ExecutionGeometry 与 Metal ABI 缺口

状态：**A2 已通过**。范围严格限定在 A2：`TargetAbiDeriver` /
`TensorMemoryContract` 派生、独立 fallback `ExecutionGeometry`、符号几何/`when`/Derived Scalars/
MSL 反射按名绑定、多阶段与 output 读写、`CandidateArtifact`/Canonical Bundle、硬件中立 prepare/run
生命周期，以及 `read_write`/workspace/计时协议。A3 的证据底座接入（TaskLocator、artifact_set_digest、
schema 4、run_config schema 3）、A4 的真实 Mac 垂直切片、A5/A6 未开始；清微 NPU 工具链与 CUDA/CANN
没有进入本阶段。

## 1. 变更

生产代码：

- `tcenv/track/abi.py`（新）
  - 唯一的 `TargetAbiDeriver`：`(SemanticInstanceV2, TargetProfile 的通用上限) → TensorMemoryContract`。
    锁定张量 identity（name/role/dtype/space/access/shape/strides）、acc dtype、容差与目标 buffer 槽位预算；
    没有 tile/grid/threads/num_warps/fallback 几何。
  - 只读 target 的 `raw_limits`（`max_buffer_index`/`max_threads_per_threadgroup`/
    `max_threadgroup_memory_bytes`，可选设备缓冲长度）；缺项即拒绝，不用默认值。
  - workspace 张量是 ABI 参数，但不是 reference 初值/结果；strided 张量按实际可寻址跨度
    （`tensor_span_bytes`）而不是 `numel` 计字节。
- `tcenv/track/expr.py`（新）
  - 唯一的整数/谓词表达式求值器：JSON term 与 `taic-launch` 文本表达式共用同一语法（`+ - * /`、
    括号、标识符）与闭集函数（`ceil_div/min/max`、比较、`and/or/not`）；整数除法必须整除。
- `tcenv/track/geometry.py`（新）
  - typed `resolve_geometry`：求值 grid/threads/threadgroup/workspace/`when`/Derived Scalars；
    符号与整数 attrs 是名字空间，派生标量可按名参与几何但只能依赖 symbols/attrs；未知名字、
    未声明 workspace、同一 workspace 两种清零策略、零激活 stage、越界线程/threadgroup 均拒绝。
  - `geometry_pair`/`select_geometry`：fallback 是独立 `ExecutionGeometry`（`source=fallback`），
    不被候选嵌入或推导；两者都进入执行身份；fallback 必须显式 `allow_fallback` 才能使用，
    `used_fallback` 进入证据。
  - `dispatch_parity` 比较记录几何与逐段实际 dispatch；`selection_parity` 在 dispatch 之前先比较
    provider，worker 错用 fallback 即使 stage 合法也是 mismatch。
- `tcenv/track/lifecycle.py`（新）
  - 硬件中立 prepare/run 生命周期：host 侧只能产出几何、资源与 launch 参数；输入相关 prepare 必须
    `inside_timing`；可复用的输入无关步骤由 candidate/target/instance/step 计算缓存身份（不接受手写）；
    run 侧恰好是已求值几何的激活 stage。候选 `host_tiling`/`schedule` entry 与 prepare 步骤必须一致，
    Host Tiling 不能被声明后忽略。生命周期文档版本化并进入 Canonical Bundle 摘要。
- `tcenv/track/protocol.py`（新）
  - `read_write` 在 out1/out2/out3 前都恢复初值、不毒化、不参与 unwritten 统计；纯 write 输出在
    out1/out3 毒化、out2 清零；`GUARD_PATTERN=0xCD`。
  - workspace：benchmark 只清候选声明 `zero` 的区域，未声明区域不插计时内清零核；correctness 的
    out1/out3 毒化、out2 清零。
  - 连续 reps 之后只允许 guard band / 越界 / 硬件状态检查；`TimingDiscipline` 明确
    `fresh_rotation` 或 `stateful`，两者互斥。
  - `check_prepare_timing`：输入相关 prepare 在计时外一律拒绝（带缓存的也一样）；cached 步骤必须有
    缓存身份；Host Tiling 不得计算 reference。
- `tcenv/track/bundle.py`（新）
  - `CanonicalBundle`：候选 entries 按路径 canonical 排序；`candidate_sha256` 仍只是候选提交身份
    （msl-single 是单文件字节 SHA-256），`bundle_digest` 是候选 entries + 冻结几何 + 可选生命周期；
    几何或生命周期变化改变构建对象摘要，不改变提交身份。
- `tcenv/backends/metal/stage_binding.py`（新）
  - 用 MSL 反射做 per-stage 按名绑定：每个 stage 自己的连续槽位；张量 access/dtype/宽度校验；
    Derived Scalars 按名 `setBytes`；未激活 stage 不参与该实例 ABI；每个结果张量必须至少被一个
    激活 stage 写入。
- `tcenv/backends/metal/source_builder.py`、`backends/metal/build_profiles.json`
  - 诊断 build profile 表从 Python 字面量迁到唯一 JSON 文档，唯一读取器 `load_build_profiles()`；
    `source_builder.py` 除该注册块外与 A2 起点逐字节相同（verify.py 检查）。
- 薄接点：`tcenv/contract_errors.py`/`tcenv/taskcontract/errors.py` 增加 `GeometryError`
  （`execution_geometry_invalid`）；`tcenv/opspec/v2.py` 的 reference 初值/结果投影排除
  `space=workspace`；`tcenv/taskcontract/loader.py` 让 workspace 张量成为正常声明（A1 曾显式拒绝）；
  `tcenv/track/__init__.py` 导出 A2 接口。

## 2. 合同行为

- **ABI 与几何分权**：`TargetAbiDeriver` 只锁 ABI/内存/数值；grid/threads/threadgroup/workspace/
  Derived Scalars 全部由候选 `ExecutionGeometry` 所有。ABI 文档里没有 tile/grid/threads/fallback。
- **fallback 独立**：`source` 必须是 `candidate`/`fallback`；fallback 不能冒充候选，候选失败时只有
  显式 `allow_fallback` 才能使用，`used_fallback` 与 pair identity 进入证据。
- **符号几何一致求值**：JSON term 与文本表达式共用同一求值器；除不尽、未知函数、未知名字都拒绝。
- **when**：stage 谓词只在该实例求值；全部不激活的几何拒绝，不产生空 dispatch。
- **派生标量**：只能依赖 symbols/attrs，不能互相依赖/遮蔽张量或符号；可按名参与 grid/threads/
  threadgroup/`when`；MSL 侧必须由本 stage 的整数标量参数按名绑定（`setBytes`），未绑定即拒绝。
- **多阶段/output 读写**：一个 stage 可以只绑定张量子集；结果张量必须被某个激活 stage 写入；
  `read_write` 必须反射为可写且非 `const`。
- **read_write/workspace/计时**：见 §1 `protocol.py`；正确性三连跑、unwritten 跳过、guard pattern、
  fresh/stateful 互斥、workspace 只清声明区域、输入相关 prepare 必须计时。
- **prepare/run 生命周期**：host 侧不计算 reference/不预处理计时外的输入；缓存身份由作用域计算；
  candidate 的 Host Tiling entry 必须有对应 prepare 步骤，反之亦然。
- **作者中立**：`CandidateArtifact`/`ExecutionGeometry`/生命周期都没有 author/LLM/committee/session
  字段；相同字节得到相同 verdict/identity。
- **没有 v2 循环/goto 风格审查**：v1 的 `screen.py` 仍是 v1 防线；v2 投递面不 import 它，也不新增
  pattern gate；`goto`/`while(true)`/状态机候选字节一律 accepted。
- **build_profiles 唯一读取器**：只有 `backends/metal/build_profiles.json` + `load_build_profiles()`；
  Python 里不再有第二份 profile 表。

## 5. 结果

结果（2026-10-31）：

- `verify.py`：manifest OK（26 个文件）、A2 起点冻结面未改动（30 个路径）、
  `source_builder.py` 只在 profile 注册块改变（去掉注册块后与 A2 起点逐字节相同）、A2 平台边界 OK、
  33 个稳定负例 node id 存在、self-test **31 项**全部通过、固定 pytest **270 passed**。
- 安全套件（`uv run pytest -q -m 'not gpu and not llm and not slow'`）为 **3413 passed、33 failed、
  7 skipped**。33 个失败全部与 A2 无关，且与 A1 登记的同一族完全对应：18 个 `OSError`
  （本会话 `TMPDIR` 过长导致 AF_UNIX 路径超限）、5 个 `PermissionError`（沙箱进程/信号操作）、
  8 个依赖宿主 probe/selfcheck 记录的断言（含 `git apply` 的 harness IndexError），以及 G0
  `baseline-failures.json` 已登记的 `ArtifactBundle.materialize(anchor)` 草稿 TypeError。
  没有删除或弱化任何测试，也没有为全绿修改无关代码；A2 新增/固定的用例全部通过。串行复跑方式：
  `uv run pytest -q -n 0 <nodeid>`。
- 本阶段没有运行 GPU、NPU、`taic run`、模型 kernel 搜索或任何付费实验。

独立复核中发现并修正的问题（均有稳定测试）：

1. 最初的几何实现不允许 grid/threads/`when` 引用本 stage 的 Derived Scalar，这是计划没有规定的
   额外表达限制；已改为与 symbol/attr 一致，`BLOCKS` 可同时作为 grid 和 `setBytes` 值，
   除不尽/未知名字仍拒绝。
2. 最初的 prepare 规则允许“输入相关 + cached + 计时外”通过，违反“输入相关 prepare 必须计时”；
   已改为输入相关一律必须在计时内，cached 一律要求缓存身份（生命周期按作用域计算）。
3. 同一 workspace 的两种清零策略最初只在读取属性时才报错，已改为 `resolve_geometry` 当场拒绝。
4. strided ABI 张量最初按 `numel` 计字节，会低估可寻址跨度；已按最大偏移计算（ABI 长度检查与
   per-stage binding 共用 `tensor_span_bytes`）。
5. 派生标量的 `{"-": "K"}` 单参数拼写与 `{"-": ["K"]}` 行为不一致，已归一为同一应用路径。
