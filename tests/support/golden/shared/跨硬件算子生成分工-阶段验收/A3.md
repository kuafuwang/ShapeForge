## 2. 合同行为

- **提交身份与构建身份分开**：构建前 `candidate_sha256` 只覆盖候选源 entries；构建后几何 entry 进入
  `artifact_set_digest`，确认门用该 digest 比较几何漂移；`native_digest` 是审计副本，不是第二发布谓词。
- **Track 不提供算法**：track 只描述交付机制；renderer 只格式化已声明事实，不能按 op/shape 提供 tiling。
  正式 track 未知、版本未知或 `interface_only` 一律拒绝，v2 没有隐式 track。
- **发现与重建**：v2 由目录 `opspec.json` 的 `spec_version` 决定，v1 不进入 v2 发现；暂存任务在 worker
  重建后必须得到同一 locator 指纹，否则拒绝。
- **知识边界**：`task_pack_digest` 只覆盖任务文件 + 中立代码闭包；`guidance_catalog.md`/`skills/` 只进入
  `run_config.agent_guidance`。
- **恢复**：schema 3 的 v1/v2 身份字段在 resume 前校验；历史 schema 2 run 仍可读，不迁移、不回填。
- **envelope 不丢段**：prune/自检/worker/evaluate_task 要么整份拒绝，要么完整解码；不存在“只取第一段”。

### 2.1 复核修复（独立负例发现，2026-10-31）

首轮 268 项通过后，独立负例发现六个实质缺口；以下修复都在本阶段完成，并各有固定 node id：

1. **envelope 缺省身份**：`EvaluationRequest` 在缺省赋值前先解码合法 envelope，缺省/`from_dict`/
   显式三条路径都只能得到候选 manifest digest；显式 transport 哈希被拒绝。覆盖
   `test_evaluation_request_uses_the_manifest_identity_on_default_and_from_dict`。
2. **staged 路径逃逸**：`_safe_relative_path` 拒绝绝对路径、盘符、反斜杠、`.`/`..` 组件和非规范拼写；
   `StagedTaskPack` 构造与 `rebuild` 写盘前都验证 `task_id` 与全部文件名，并拒绝穿过 symlink 的
   重建。覆盖 `test_staged_pack_refuses_absolute_escape_paths_before_writing_anything`，断言外部文件
   绝不产生。
3. **旧 locator digest**：`TaskLocator.load` 重新装配合同、用保留的 `code_root` 重算部署闭包，并比对
   完整 locator 文档；任务文件或代码闭包在发现后漂移即拒绝，`evaluate_task` 不再用旧 digest 评测新
   字节。覆盖 `test_load_refuses_a_task_file_or_code_closure_that_drifted_after_discovery`、
   `test_evaluate_task_refuses_a_task_that_drifted_after_discovery`。
4. **schema 资源闭包**：静态 import 闭包自动纳入每个已包含模块旁的 `schema/*.json`（如
   `opspec.v2.schema.json`、`baselines.v1.schema.json`），并进入同一 `deployment_pack_digest`；
   独立 worker 只部署闭包即可发现任务，删除 schema 则失败；schema 变化改变 digest。覆盖
   `test_the_pack_closure_runs_in_a_worker_without_the_control_host_repo`、
   `test_a_runtime_schema_change_moves_the_deployment_pack_digest`。
5. **schema 4 读取**：`evaluate_task` 用唯一 `EvalReport.from_json` 闭集读取器验证并规范化报告；缺
   `schema_version`、缺字段或自由字段拒绝，报告 `build.candidate_sha256` 也必须等于候选身份。测试
   替身改为 `project_full` + 真实 `EvalReport`，并加 `missing_version`/`free_field`/`missing_build`
   负例；`test_report_schema4` 的调用点登记表加入 `tcenv/taskcontract/runner.py`。
6. **分段头 SHA/段数**：解码端校验每个 `taic-file` 头 SHA 与 manifest 及实际 body 一致，并执行与编码
   端相同的 64 段上限。覆盖 `test_a_tampered_taic_file_header_sha_is_refused`、
   `test_the_decoder_enforces_the_same_segment_limit_as_the_encoder`。
7. **运行时 schema symlink**：`code_import_closure` 不再对 symlink schema 静默 `continue`。schema 目录
   本身是 symlink、schema 文件是 symlink、路径穿越 symlink 或不是常规文件，一律抛
   `PackClosureError`；`task_pack_closure`、`discover_standard_tasks` 和 `TaskLocator.load()` 因此都
   失败，不会产生省略该资源的 digest，也不会出现 `ACCEPTED_DRIFT`。覆盖
   `test_a_symlinked_runtime_schema_is_refused_by_closure_discovery_and_load`、
   `test_a_symlinked_schema_directory_is_refused`，以及独立 worker 中“把 schema 换成闭包外 symlink”
   的 discovery 失败断言。
8. **嵌套 schema 目录 symlink**：`Path.rglob` 不进入目录 symlink，原实现因此看不到
   `schema/nested -> 闭包外目录` 子树。`code_import_closure` 改为 `os.walk(..., followlinks=False)`
   的显式遍历，在每一层检查所有目录项/文件名：嵌套目录 symlink、嵌套文件 symlink、非常规文件和
   解析出 code root 的资源一律拒绝；正常 `.json` 资源仍进入同一摘要。覆盖
   `test_a_nested_symlinked_schema_directory_is_refused`（closure/pack/discovery/load 全拒绝，外部
   `extra.json` 修改后仍拒绝）。
