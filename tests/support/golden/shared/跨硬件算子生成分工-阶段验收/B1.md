# B1：gemv 与 rope 迁到 v2 标准入口

## 这批做了什么

把 `preserved_v1_out_of_scope` 里的前两道题——`gemv`、`rope`——迁到 v2 标准任务目录，
并在同一批里删除它们的 v1 装配与 Metal `LoweringProfile`：

| 项 | 内容 |
| --- | --- |
| 迁移任务 | `gemv`、`rope`（各 fp16/bf16 × paper/small，共 8 组合） |
| 新写入 | `opspec.json`（`spec_version: 2`）、`reference.py`、`reference.json`、`baselines.json`、`baselines.py`、`display.json` |
| 删除 | `task.py`、`track.json`、`kernel_triton.py`、`kernel_triton_msl.py`、`naive.metal`、`__init__.py`、`__pycache__` |
| 退役 profile | `metal-gemv`、`metal-rope`（`tcenv/backends/metal/lowering.py`） |
| v1 registry | `tasks/__init__.py` 的 `TASK_NAMES` 移除两题；`get_task` 按 `spec_version` 做 typed 拒绝 |
| 保留候选 | 两题的 naive 候选文本存于 `evidence/candidates/`，供 GPU 切片使用 |
| 附带修正 | `tcenv.cli tasks` 默认列 v2 标准目录，v1 保留题移到 `--legacy`；`scripts/doctor.py` 同步 |

## 边界怎么算（不改 G0/A5/A6）

G0 的 `migration-boundary.json`、A5/A6 的验收文档与 manifest **一个字节都没改**。
本批只新增 `B1/boundary.json`，当前边界由它派生：

```
当前 v1 保留集 = G0 preserved_v1_out_of_scope − 本批 migrated
               = conv2d, flash_attention, lion, bitdelta_gemm, mamba2_chunk_scan,
                 sem_attention_odd_scale, sem_int dynamic family
当前已迁移集   = G0 migration_candidates(16) + 本批 migrated(2) = 18 题
```

`tests/support/boundaries.py` 是这条派生的唯一实现，`frozen_tasks.py` / `v1_tasks.py` /
`test_a6_retirement.py` / `test_v2_mapping.py` 都改从它读取，不再各自手抄清单。
后续批次（B2、B3…）各写各的 `boundary.json`，同一条规则继续适用。

## 等价性证据（这批的核心）

G0 冻结语料里**没有**这两题的任何张量，所以 A5 的 82 组合对照不能直接复用。
本批在删除 v1 之前，先用 v1 自己的评测路径冻结了 oracle：

```
生成器：tasks.get_task(task, dtype, size) + tcenv.backends.metal.testing.prepare_case
种子：  seed = 7919 * (case_index + 1) + {0, 7, 1234}（与 G0 同一公式）
覆盖：  8 组合 × 6 case × 3 seed = 144 条记录
内容：  输入原始字节 sha256、fp64 参考输出字节 sha256、误差尺度字节 sha256
文件：  evidence/v1-frozen.json
```

`compare.py` 随后用 v2 合同重放同样的 `(case, seed)`，逐项比对：

| 组合 | 记录 | 输入逐字节 | 参考逐字节 | 尺度逐字节 |
| --- | --- | --- | --- | --- |
| gemv fp16/bf16 × paper/small（4） | 18/组合 | 36/36 | 18/18 | 18/18 |
| rope fp16/bf16 × paper/small（4） | 18/组合 | 18/18 | 18/18 | 18/18 |

结果：`evidence/compare-report.json`，**全部逐字节一致**，不是容差内一致。
此外断言 `numerics`/`sizes`/`work_accounting`/`attrs`/`tensors`/`symbols`/`spec_params`/
`formula` 等语义字段在 v1→v2 映射中原样保留（只允许 `spec_version`/`uses`/`discovery` 变化）。

迁移中抓到并修正的一处真实偏差：`gemv` 的 v1 合同声明 `cases.inputs.ieee._inject = ["A"]`，
即 IEEE 特值**只注入 A**。初版 `reference.py` 给 `x` 也注入了，被冻结证据立即查出。
这正说明"先冻结、再迁移、再比对"这条顺序是必要的。

## 真机切片（GPU）

`tests/backends/metal/test_task_migration_b1_gpu.py`（`-m gpu`，需明确授权）用归档的 naive
候选在真实 v2 评测路径上跑 small/fp16：候选正文 + v1 的 grid/threads（写成 `taic-launch`
块）+ 候选自有的 `BLOCK_M`/`BLOCK_S` 常量。合同符号与 attrs 由 v2 合同头提供，候选重复
声明会被编译器拒绝——这正是候选/harness 边界应该有的行为。

结果：`evidence/gpu-gemv.json`、`evidence/gpu-rope.json`，两题均 `status=ok`、ABI 通过、
正确性通过、计时 > 0，真实 dispatch 与 v1 的 grid/threads 一致。
